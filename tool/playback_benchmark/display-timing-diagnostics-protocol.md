# R5 显示调度延迟诊断（2026-10-09，base e923bb8）

目标是区分显示tick到达应用回调前的间隔、tick执行耗时与主队列延迟；不能把先前5帧丢弃直接归因于某个线程。仅改macOS测试及镜像/诊断工具，不修改生产调度、容量、时钟或候选默认开关。

在原真实decoded观察中，只有显式 `YL_DECODED_TIMING_DIAGNOSTICS=1` 才启动测试记录器；普通回归不启用后台探针。包装已有YlDisplayTimer的onTick，测进入间隔与同步处理耗时。单独50ms后台定时器向主队列投递至多一个未完成探针，记录投递至执行延迟；后台采样间隔>100ms另记producerGap，避免把探针自身断供误判为主线程畅通。tickGap/tickWork/mainQueue阈值30ms仅筛选诊断记录，不改变原有零丢帧或播放门限。

只保留32个标量异常事件、各类累计计数和最大值；不保留帧、媒体、闭包历史或对象地址。probeSent/completed/skipped与pending用于检查背压，stop后已投递闭包不得更新记录；disabled不创建计时器/投递工作。快照每5s随原始行保存，事件被淘汰时不得用“未观察到”推出不存在。计时包围的是应用onTick，位于生产refreshCadence之后；不宣称已测到硬件vsync或全部显示驱动耗时。

先以受控时钟和派发边界验证慢tick、主队列积压、后台探针间隔、32条历史和stop隔离的RED→GREEN；Python验证拒绝伪造/缺字段/非单调记录，并保持失败采样可诊断。完成后仅执行一次带新诊断的30s短观察（原90s用例、180s父进程）；零丢帧失败照常保留，不重复求通过、不接1200s长播。该观察不得作为未加探针长播的短门禁。

对丢帧前窗口匹配重叠的异常事件，只报告时间相关。tickWork慢支持应用处理耗时；mainQueue慢支持主队列任务延迟；producerGap提示后台探针覆盖不足。仅tickGap而无对应已保留事件不能证明OS/显示驱动根因。没有再次丢帧时只能证明本次未复现，不能抹去R5失败。完整回归和长播保持待验；iOS未受影响，不新增iOS执行。

后续iOS设备偏好已由用户明确为 **iPhone 18 Pro Max**；今后优先该模拟器，记录实际型号和系统版本；若不可用再说明，不静默换成Pro或其他设备。
