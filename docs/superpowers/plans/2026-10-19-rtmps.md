# RTMPS Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans with independent transport/tests delegated through superpowers:dispatching-parallel-agents. Steps use checkboxes.

**Goal:** Support authenticated RTMPS live input for ordinary Apple playback and AirPlay.
**Architecture:** Secure RTMP recipes use Network.framework TLS before the unchanged protocol handshake. Routing reuses existing fallback and retained HLS workers; TLS failures terminate without spending retry budgets.
**Tech Stack:** Swift, Network/Security, existing FFmpeg/AVFoundation, Dart diagnostics.
**Spec:** `docs/superpowers/specs/2026-10-19-rtmps-design.md`

## Global Constraints

- iOS15/macOS12, existing codecs/transport policies and AirPlay limits.
- System trust and hostname verification, TLS1.2 minimum, no plaintext downgrade.
- No new public APIs, binary rebuild, trust-store edits or automatic commits.

## Review Focus

- Untrusted or wrong-host certificates fail terminally without reconnect loops.
- Cancellation and timeout cover a silent TLS handshake before any RTMP payload.
- RTMPS automatic-format AirPlay enters RTMP input rather than HTTP inspection.
- Explicit/default ports and original scheme/playpath reach the protocol correctly.
- Plain RTMP and existing AirPlay paths keep their previous behavior.
