# 有界恢复续轮与取消归因

用户明确批准：每轮2次预约、每播放源累计4次；真实高档至少2秒且48帧；预约间隔至少30秒；原双8秒窗口、每窗3请求、1.25倍目标带宽、缓冲5秒/剩余20秒、取消不退款均保留。采用系统排障、先反例后实现、精简实现与一次受影响验证。独立工具验证实现可按 subagent-driven-development 分工，禁止重跑未变化内容。

- [x] 取消归因：在代理所有权锁内固定终止事实；观察者在锁外交付。确定性旧顺序反例已失败，新顺序通过；真实代理定向测试不得放宽原断言。
- [x] 生产策略：总 attempts 单调至4；第一轮有效上限2。成功安装后出现新的连续高档发布窗口才将有效上限扩至4。保持每轮最多2次、总数不退款；所有预约至少相隔30秒，冷却期间继续收集原带宽窗口。
- [x] 高档证明：发布帧同代际、同尺寸，位置严格推进，帧间隔不超过0.5秒；至少48帧且跨度2秒。意图/凭据变化及不适用播放状态清空窗口；单纯presentationSize不能续轮。新窗口开始时间不得早于最近成功安装。
- [x] 证据：生产policySamplingVersion升为3，决策携带budgetVersion=2、roundLimit(2或4)、lastReservation、lastInstallation、highFrameCount/highFrameSeconds/highFrameStart。旧v1/v2验证保持原契约；新v3独立校验总预算、冷却和真实帧证明，新增续轮专项不能冒充旧的无第三次预约专项。
- [x] 验证新旧策略、取消/失败不退款、冷却、短高档/暂停/过期帧和总上限；完成一轮当前真机有效再次降档采集，保持失败和物理输出缺口。

契约补充：有效上限由2扩至4只发生一次，已使用次数不减少。成功安装的时间由控制器完成回调记录。上限4耗尽后继续自然播放，不再重建；只有新公开Load的新source identity重置。冷却不改变0.5/1秒的票据退避或2秒准备/5秒票据时效。取消归因修复不声称历史未知请求未发包或已被服务器接收。
