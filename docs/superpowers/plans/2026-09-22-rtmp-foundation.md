# RTMP 播放基础实施计划

> 依据：[已授权扩展需求](../specs/2026-09-20-playback-expansion-requirements.md)，重点 REQ-07/08/13/15、CAP-RTMP、REG-NET。基线 `eee8689`。按 subagent-driven-development 执行，任务后复审，末尾进行整阶段复审。此计划不是已发布支持声明。

## 架构与本批边界

内核在各平台自行接收 RTMP、输出 FLV 字节，复用 Android Media3 FLV 和 Apple custom AVIO / VideoToolbox / AudioToolbox 路线。不增加商业 SDK，不改变 FFmpeg 网络禁用制品。原生 Swift/Kotlin 协议实现采用相同限额与独立对端验证。

本批实现标准 `rtmp://` TCP 接收、简单 v3 握手、经典 AVC/H.264 视频与可选 AAC 音频、live 自动/显式意图。RTMPS、增强 RTMP、隧道、发布、用户信息认证、服务器重定向、DVR、纯音频和其他编码分别保持不支持。HTTP 请求元数据、HTTP managed 策略与严格 bounded 缓冲不可悄悄映射；此批明确拒绝这些组合。后续范围仍在总需求中。

不新增容器枚举：RTMP 是传输，自动/flv 提示进入专门路由。无新增桥接字段，保留 private schema 3 / public SPI 2。平台须在连接前校验，assess 与 load 一致。原始 URI 保持身份；不经过外部 JS 模块或公共本机 HTTP 中转。

## Global Constraints

- No commercial SDK; preserve deployment floors Android API 24, iOS 15, macOS 12, existing HTTP/DASH behavior, candidate rollback, cancellation, audio ownership and hardwareRequired guarantees. Serialize all native/Flutter builds across platforms. Never change pinned native artifacts without matching rebuild/provenance.
- Public YlNetworkSource admits syntactically valid rtmp and rtmps URIs. Native routing supports only rtmp + automatic/flv + automatic/live in this phase; unsupported variants return stable safe errors before I/O. Reject userinfo, fragments, malformed escapes, decoded controls, empty app/playpath, invalid explicit ports, and URIs over 8192 UTF-8 bytes. Default RTMP port is 1935. URI lexical checks apply to the supplied Uri serialization; normalization already done by Dart Uri.parse cannot be recovered. The first raw path segment is app; remaining raw path plus raw query is playpath (preserve percent spelling and plus). No credentials or URI text may enter diagnostics.
- Nonempty HTTP headers/credentials, managed HTTP network policy, bounded buffer strategy, VOD intent, nonzero initial start and all runtime seekTo positions (including zero) are unsupported for RTMP; never silently ignore them. Automatic/lowLatency/smoothPlayback remain optimization goals, not measured latency promises. RTMPS/enhanced/other codecs are explicit unsupported rows. Incompatible explicit format hints return container.unsupported; unsupported intent/start/headers/network/buffer combinations return policy.unsupported consistently across platforms.
- Own and publish cancellation before DNS/connect/read/write. Absolute setup deadline 10 s covers DNS/TCP/handshake/connect/createStream/play and valid AVC configuration plus first nonempty coded AVC media (configuration, AAC or control traffic alone cannot complete setup); media inactivity deadline 15 s resets only on nonempty accepted coded AVC/AAC media payload, not control traffic, metadata, repeated codec configuration or video EOS chatter. Established inactivity counts active read demand/wait; suspend it while the consumer is paused/backpressured, retaining the remaining budget across metadata/control-only read returns. Consumer idle time must not close a healthy source; do not reset the inactivity allowance on each read entry. Public player pause must also suspend an already outstanding established read and defer automatic reconnect work; source-only idle between reads is insufficient. Resume retains the source/parser and remaining allowance, and does not reset, refund, or double-charge recovery attempts. Stop while paused still cancels input and scheduled work. Initial setup remains absolute. Socket close wakes blocked I/O. Android API 24 blocking system DNS may survive cancellation in a fixed global pool of at most 2 lookups with no unbounded queue; retain admission until lookup actually exits, cancel operation promptly and discard late completion. Document this OS boundary; do not claim DNS thread termination.
- Initial inbound chunk size 128; accepted peer chunk size 1..65536; at most 32 chunk-stream states; one media message at most 4 MiB, control/AMF message at most 64 KiB, aggregate in-flight payload at most 8 MiB. AMF depth 8, at most 256 entries per message, string at most 16 KiB. Pending outbound control/chunk bytes are capped at 64 KiB; hard/soft/dynamic peer bandwidth credit and modular acknowledgements must be enforced without recursive parser reads. Receive acknowledgements must be sent as the window is crossed during message reassembly, not only after a complete media message. Check limits before allocation, demand-driven output/backpressure, release buffers on cancellation/failure. These are fixed source workspace limits, not fulfillment of YlBufferStrategy.bounded.
- Handshake order: send C0/C1, receive S0/S1, send C2, then receive S2 before commands; do not deadlock by waiting for S2 before C2. Validate echoed random data (not the peer timing field). Implement chunk fmt 0/1/2/3, extended timestamps, interleaving, abort, acknowledgements/window/peer bandwidth and ping response with bounded state. AMF0 connect/createStream/play validates transaction/status and stream IDs; server strings are never exposed. Unsupported encodings/protocol messages fail safely. FLV startup flags reflect tracks actually configured before the first video keyframe; never advertise phantom audio. Track layout and AVC/AAC decoder configuration are fixed per epoch: identical repeated config is allowed, but a new late AAC track or changed configuration fails before delivery with container.rtmp_track_layout_changed and safe reload guidance. FLV retains AVC composition offset and AAC config. Detect unsupported enhanced/other codec before exposing it to the decoder.
- Initial candidate gets one attempt and rolls back on failure within the existing Android candidate activation deadline; Apple must retain its own finite opening deadline because it has no equivalent total coordinator timeout; no reconnect chain before commit. There is one RTMP recovery authority per committed load: no nested transport/Media3/health retries. At most 3 automatic failure-recovery attempts per committed load, delays 500/1000/2000 ms, budget never resets at first frame. A user seekToLiveEdge or lifecycle/rollback restore may make one explicit fresh live attempt without consuming or resetting the automatic budget; a transient failure during that attempt may use only the same remaining automatic budget. No hidden per-open retry counter. Successful foreground/rollback transitions must not deplete recovery allowance. Only transient connection loss/timeouts retry; denied stream, unsupported/protocol-invalid, cancellation and resource limits are permanent. A reconnect creates a fresh extractor/demux epoch and rechecks codecs/hardware policy. Cancellation cancels backoff and all old-generation work. Timestamp reset/backward discontinuity beyond 2 s or 32-bit wrap starts a fresh epoch through the same bounded reconnect budget; do not append a fresh FLV header into the old demux. Small audio/video interleave reordering is allowed per-track, not a global monotonic assumption.
- Stable codes: network.rtmp_handshake_failed (connect/setup), network.rtmp_disconnected (read/playback), network.rtmp_stream_unavailable (server denial, nonretryable), container.rtmp_track_layout_changed (late track/config change, nonretryable), network.protocol_unsupported, container.unsupported, policy.unsupported, resource.exhausted. Preserve existing state session identity and diagnostic correlation; identify phase through stable codes and safe actionable messages (current failure wire has no dedicated phase field), never raw exception/server text. Add timeout reason only through existing safe typed fields or messages, not string parsing.
- Root controls plans/docs/review; each implementation task has a fresh worker, no worker-spawned subagents. Do not commit or push task changes automatically; root already made the user-requested baseline commit. Review packages include uncommitted and newly added files. Meaningful red/green tests precede behavior changes; do not repeat previously green unrelated whole suites.

## Task 1: Public contract and diagnostic boundary

Leave RTMPS capability unsupported to native assessment, just as a recognized unsupported format; rtmp source with incompatible policies is structurally representable and native assessment must explain unsupported policy. Add the three RTMP-specific stable failure code constants / safe default messages to Dart diagnostics and tests (use existing extensible code conventions), plus safe actionable guidance for existing native network.protocol_unsupported so RTMPS/unsupported protocol errors do not degrade to generic prose. Messages identify handshake versus unavailable stream versus playback disconnection and useful next action without guessing authentication cause. Ensure native-supplied known safe fields keep phase/session/correlation; unknown text remains redacted.

Update the optional resolver's toNetworkSource to permit header-free RTMP results using core validation; RTMPS remains unsupported conversion until native transport exists. Reject RTMP results with HTTP headers explicitly rather than dropping them. Preserve HTTP behavior and expiry semantics. Locate and update corresponding contract/validation/resolver tests; use targeted flutter test/analyze commands, report exact counts. No native files in this task.
