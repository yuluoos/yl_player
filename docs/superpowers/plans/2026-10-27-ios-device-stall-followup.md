# 真机停顿复现与恢复路径补验

基线 8332c9e9，codex/abr-recovery。使用系统排查与集中验收，沿用真机开发签名授权，不合并或发布，不放宽门槛。上一轮已补齐策略精确判定与音频/生命周期诊断，本轮从原始数据继续。

- [x] 原 down-and-recover-v1 自动候选复测，已有 stall-and-recover-v1 / disconnect-and-recover-v1 单独受控故障，原配置 pause-first 补验。记录预登记顺序、每次失败及未触发，不把不同 profile 冒充原场景通过。
- [x] 根据真实窗口/缓冲/后端错误/通知定位原因；必要时在单独诊断条件下验证同源替换，明确强制操作不等于自动触发。只对可复现且因果确认问题修改代码。
- [x] 受影响范围统一检查和独立复审，保留缺设备/授权与物理音画输出缺口。
- [x] 归档原始失败和完整来源、核对旧证据并更新发布台账。无证据的能力保持未验收。

冻结策略：955000 bit/s，两次连续 8 秒窗口，每窗至少 3 新请求，连续缓冲至少 5 秒、剩余至少 20 秒，先高后低且有逾期，最多两次源级预算、500/1000 ms 退避。自然未触发不能算自动替换/退避覆盖。原生140秒/采集240秒上限不变。

本轮实施与检查已执行，整体验收未完成。十轮完整采集；另登记的带宽/延迟诊断取得一次自动安装、首次撤销后第二次安装及两级退避，发布空档仍约189/211ms。原配置未触发，旧终末停顿未复现。仅修复摘要/失败回执，不声称修复播放器停顿；详见 ../reports/2026-10-27-ios-device-stall-followup.md。
