# 音频已消费输入的容量失败处理

基线 16869125；沿用 P03 严格资源策略、P08 可控资源边界和集中验收，当前工作树独立实施。不推送、不发布，不修改另一聊天 iOS 恢复。

问题：legacy enqueue 在转换后发现实际 PCM 超过容量却返回 wouldExceed，上游保留并重放已消费的压缩包。terminal 路径已有明确失败处理。

- [x] RED：真实 AAC 短报 duration、确定性的字节/时长超限、pipeline 不留待重试包；保留转换前背压正常重试控制。
- [x] 最小生产修复：转换后超限抛现有安全 policy.unsupported；不放宽限额，不引入额外待播缓冲或修改转换前背压。
- [x] GREEN 与集中验证：共享原生测试、macOS 受影响音频/管线矩阵、iOS 编译（不操作设备/恢复用例）、工具与台账检查；一次独立综合复审。
- [x] 记录原始失败/跳过、源码身份和未完成项。此修复不证明系统 A5 上界、119.084ms READY 根因或物理输出资格。

复审重点：转换后错误不得触发包重放；拒绝 PCM 的所有权及时释放；已有队列、转换前背压及 reset 后新代正常；错误沿现有 pipeline 公开，不增加新公共协议；未验证设备和现有失败不隐去。

集中矩阵发现 DTS 正常容器取整导致估算不足（10000us < 10666us），新增真实解码估算 RED。首个按8192帧估算时长的方案使既有100ms窗口失败，独立复审还指出32kHz/0.25倍速可能永久背压；该候选已放弃，失败证据保留。

最终方案：完整纯core包以帧头块数/采样率向上取整，支持16/14-bit BE/LE，扩展/未知结构仍用decoder cap；字节上限不变。renderer 对单包估算超过有效总时长窗口明确失败，与容量检查共用同一倍速/严格预算规则。新增共享测试合计6项，覆盖真实低采样率、四种打包及既有100ms窗口。修复后集中重测四类相关矩阵并定向复审，不重复未受影响的全套长耗时测试。
