# CoreAudio 容器时长与资源分配解耦

基线 d5149979，分支 codex/coreaudio-bounded-estimates。沿用已批准的P03/P08资源边界工作和集中验收；复用本聊天工作树，不操作另一聊天iOS恢复，不提交/推送/发布。

根因：AAC/MP3估算以容器duration转换帧数并相乘，六声道极大值可能溢出；iOS非batch路径进一步以该估算决定UInt32帧容量。DTS/FLAC/Opus/Vorbis已有有界来源，当前缺口是CoreAudio固定帧路径。

方案：固定帧音频的时长按已有解码帧契约计算，不信任容器duration；PCM容量保持macOS一个输出包、iOS一个包加既有headroom，分配与字节预留使用同一上界。FLAC仍由帧头精确决定，不扩展AAC/MP3支持资格、不放宽限额，不改变网络/iOS恢复逻辑。

- [x] RED：AAC立体声/六声道、MP3异常时长估算；真实AAC/MP3输出、时间与PCM容量对照。RED先检验安全上界，避免故意触发进程崩溃或巨大分配；GREEN才执行Int64极值。
- [x] 最小实现与定向验证：去除容器时长到CoreAudio内存分配的路径，保留现有iOS headroom和正常包输出。
- [x] 全部修改完成后集中macOS音频/输出/managed管线回归，iOS仅编译，工具/镜像/台账检查；一次独立复审，必要时仅重测修复范围。
- [x] 保存原始失败/跳过、源码及结果身份和外部缺口；不将可控缓冲修复当作A5上界或物理资格。

自查补充：低采样率MP3配置必须为576帧，新增真实帧与40ms窗口回归；AAC960配置在当前CoreAudio不支持，保留原始探测失败，不扩展资格。
