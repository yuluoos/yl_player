## 本轮结论

原配置三次运行（当前制品两次、旧制品对照一次）均完整到片尾、保持低档，每轮十个完整窗口均不足 955000 bit/s，因此没有预留预算或发出恢复票据。未发现策略漏发已满足条件的票据；不能据此宣称原配置自动恢复已通过，也未查明 AVPlayer 内部为何持续低档。

原 63.900 秒终末停顿未复现。新增观测补齐本地代理连接、上游任务和发送队列的边界；本轮两次原配置片尾快照中，仍被代理跟踪的活动任务和待发送回调均为零。它不能补造旧失败中缺失的边界信息，旧失败与根因待查状态保持。

两次当前制品实际替换的新帧间隔为 190.241/206.009 ms，旧制品同条件对照为 121.980 ms；本轮**没有证明空档缩短**，也不能排除观测开销或运行波动。未找到可安全删除的额外等待，未绕过精确 seek 门控或启用生产自动恢复。已完成的是诊断缺口补齐及真实路径复测，不是停顿/无缝恢复修复声明。

## 边界观测及限制

仅 Debug 新增固定数量的数字计数：接受连接、创建/恢复上游任务、收到的响应体字节、完成回调（包括已关闭连接后的回调）、取消/其他错误、带活动任务的关闭次数；另采样活动连接/任务、暂停任务、待发送回调数及最后入队/完成的设备 uptime。没有资源 URL、凭据或请求标识，也不保留不断增长的事件历史。当前 loader 替换后计数重置，不能跨 generation 相减。

两轮原配置分别接受并入队 338/335 次请求，收到 338/335 次完成回调，其中各 1 次取消、0 次其他完成错误；片尾活动任务、连接和待发送均为 0。第二轮采样曾看到 2 个待发送回调，后来归零。完成回调不等于 HTTP 成功；gauge 只统计仍被代理跟踪的记录，零值不证明已经脱离记录的底层回调全已结束，250 ms 快照也不能排除采样间的瞬态积压。这些是本轮正常结束时的边界证据，不是旧停顿的反证或根因结论。

新增真实 loopback 代理测试先因缺计数而失败。实现后又发现：客户端收到完整响应后可能先关闭连接，任务记录已移除时仍会收到 URLSession 完成回调；只在记录仍存在时计数会漏报。现将 Debug 完成计数放在查找任务记录之前，并明确等待真实完成回调。转发、关闭、取消、重试、凭据和 admission fence 的行为未改。该新增测试在请求完成后检查 cancelAll 状态；不能视为进行中取消竞争/错误分类的完整确定性覆盖。三份生产源码去除 Debug 块后与基线经空白规范化一致；这不是 Release 制品运行验收。

保留四份失败 XCTest：镜像漏模块导入、默认测试包未签名、预期红灯、完成回调计数遗漏；修正后新测试真机 1 通过。另保留缺少 build-for-testing 清单导致的采集启动失败；该次未进入媒体测试，不能算停顿或成功清理。其后才执行上述六次完整媒体采集。

两轮首次退避实际约 521.967/523.746 ms，符合 500 ms 下限；本轮未重跑第二次退避/暂停撤销，保留上轮证据及其覆盖限制。没有改预算、票据或策略条件。保留旧纹理不是新增视频帧，零清空不代表物理屏幕无黑屏；音画/字幕及真实屏幕连续性仍未验收。

将精确 seek 前移至未切换的预热解码器是后续可研究方向，但需要完整的解码器交接、时间对齐、资源预算与意图竞争验证，当前没有这条安全实现证据。[Apple 的 preroll 文档](https://developer.apple.com/documentation/avfoundation/avplayer/preroll%28atrate%3Acompletionhandler%3A%29)要求播放器已 ready 且 rate 为 0，不能直接在正在播放的当前实例上调用以消除空档。本轮不加入未经证实的预热或强制恢复逻辑。
