本轮没有复现历史 119.084ms 等待，没有取得该事件的同次线程证据，也没有基于它修改生产播放代码。任务根因项保持未完成，候选默认关闭，productionAdmission=false。

## 采集配置与验证

在原稳定门闩、owned PID 校验、完整同帧 enqueue 返回后停止、250ms 尾段及 10s 滚动窗口基础上，新增互斥的 `--thread-activity-only`：Blank + Thread Activity。默认仍是原 System Trace 配置。最初用临时包装器验证可用性，再写 RED 测试和实现。该配置仍有底层依赖，不能声称开销已更低，亦不能声称跟踪抑制了历史事件。

短测 PID 23275 正常完成。播放器导出 175,622 条 context-switch 样本，其中 73,109 条有栈，31 个线程；311,896 条线程状态中 62,655 条有 waker。恢复的原始记录实际范围：播放器 0.001481500–20.695051416s，183,008 样本；WindowServer 0.002462750–20.738260916s，68,268 样本。范围与数量证明能获取这些数据，不等于所有线程无丢失，也不是目标 119ms 覆盖证明。

测试：新增配置测试先因缺少参数失败，实现后定向 17/17 通过。全套首次 244 项中 3 项遭沙箱权限错误；相同命令在所需权限下 244/244 通过。代码复审没有阻断问题。本轮未改 Swift，无新增原生全套回归；原生短测通过，长测因系统丢弃 5 不等于 0 失败。

## 尾段线程分析

末尾两次系统丢弃的观察区间是 uptime 124931.899349–124933.911715（约 2.012s），不是精确丢弃帧时间。61 个 LayerSync 时钟对的 wall/host 中位偏移内部跨度 0.994ms；该跨度不是绝对误差界。14 组唯一 TID/状态/栈地址样本对齐 attached 与 raw，偏移 7.097983917s。

实际 raw 样本范围：播放器 0.000440083–12.887220458s，WindowServer 0.000167625–12.946897583s。上述区间落在 raw 1.029978–3.042344s 内，含播放器 18,478 条切换、18 个线程；WindowServer 10,348 条切换、13 个线程。范围覆盖不保证所有线程状态已知：播放器 TID 3844753 有约 1243.279ms Unknown，不能宣称完整无缺口的全线程证据。

该区间 WindowServer 主线程累计 Running 556.177ms，最大单段 Blocked 11.677ms，不能描述成全程停住。播放器 TID 3844754 在 raw 2.552794124s 有 14.933459ms Blocked，边界非空栈精确匹配为 `__psynch_mutexwait → recursive_mutex::lock → AVAudioEngine.outputNode → presentationAudioTime → clockObservation → YlIsolatedAudioClock.sample`；没有 waker/锁拥有者信息。这是隔离采样路径的真实锁等待，不是 119ms ready 阻塞链。另有解码/帧队列条件等待，不能仅按等待时间判作故障。

此末尾观察区间没有新增 ready 拒绝，应用播放丢帧与 stale 为 0；无法确定系统丢弃的具体帧或因果归属。保留事件切换/状态片段、对齐脚本、原始文件 SHA-256 清单，不改生产代码。
