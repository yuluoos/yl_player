# JavaScript 直播源解析模块实施记录

当前执行[独立解析模块计划](../plans/2026-09-22-script-resolver.md)，本批实施、三端受控运行验收及最终独立复审已完成，无阻塞发现。依据需求 REQ-06，模块可选，播放器内核不强制依赖；不接入商业 SDK。

## 已核实的样本契约

2026-09-22 从用户附件引用恢复九份 mytvJS 原始脚本，字节数与 SHA-256 全部与[冻结账本](../specs/2026-09-20-playback-expansion-intake.md#42-mytvjs-固定版本清单)一致。恢复阶段只做静态读取；随后以冻结原始字节执行受控宿主测试，未访问脚本实际下游服务。原始文件、来源清单和校验记录保存在当前工作区忽略目录 `.superpowers/sdd/2026-09-22-script-resolver/controlled-samples/`，限制目录及文件权限；这不是版本库中的永久分发副本，移动工作区需单独保留该归档。

确认 main 接收裸查询字符串，成功返回 JSON 字符串；同步宿主包括 `mytv.get/fetch/post/request`，request 返回 code/body，其他请求返回正文文本。三个脚本另需宿主 parseItems。CryptoJS 使用 MD5、HmacSHA256、Base64/UTF8、AES-CBC/PKCS7。全部样本有自检前导，必须用未修改的原始字节验证，不能删掉混淆代码声称兼容。

返回 error 与 url 可以同时出现，error 优先，避免将诊断 API 地址交给播放器。九份脚本均未提供明确有效期，不从 token 猜过期时间。脚本日志和任意错误正文不向公共诊断透传。大小写不同但值相同的重复头合并，冲突值拒绝；已观察到的重复 Referer 值一致。广州脚本显式提供 Host，因此仅接受与初始 URI 域名及显式端口一致的值（省略端口时按 URI 补全比较），校验后丢弃，由传输层为每跳生成；不同目标、端口或冲突值拒绝，不能用它覆盖请求路由。

## 工程边界

选择同版本 QuickJS 而不是各平台不同的 JS 引擎，使用原生工作线程、单调期限、中断回调和独立堆栈限制；同步宿主调用经请求队列交给 Dart 异步传输。官方 API 提供相关限制接口；本批已在上述三端应用验收中实测循环与正则期限、运行中取消、堆超限后的回收再用，以及宿主等待取消和服务端断连。这些有界检查不构成硬实时中断保证。[QuickJS 文档](https://bellard.org/quickjs/quickjs.html)

CryptoJS 4.2.0 用于冻结脚本所需 API 兼容，上游已停止维护；只固定依赖版本并验证所用算法，不将其用于新增凭据存储或许可证方案。[上游说明](https://github.com/brix/crypto-js/tree/4.2.0)

解析模块不自动切台、不自动替换媒体、不改变 RTMP 内核支持。它是同进程受限运行时，不宣称进程级隔离；完整 JS 兼容、真实源播放、RTMP、DRM、字幕、ABR 和杜比升级仍按各自验收行推进。

## 实施中的工程取舍与代价

以下按决定顺序记录；不改变未决产品取舍 PD-01/02/03。

1. 沿用已有功能分支与未提交工作，避免丢失前批 Apple/FEL 改动；代价是后续拆分提交需要依赖保留的快照，当前不删除验收工作区。
2. 三端固定同一 QuickJS，通过原生工作线程和 build hooks 接入；代价是增加开源 C 构建依赖，只承诺实测的同进程资源限制，不宣称进程隔离。
3. 所有调用方或脚本提供的请求头都按凭据处理，跨域后永久剥离；代价是部分跨域业务需要显式建立新来源请求配置。
4. 刷新采用再次解析，未知有效期保持未知，业务负责切台和媒体替换；代价是模块不自动安排续期。
5. 保持上游 QuickJS 字节不变，允许脚本捕获普通栈限制异常后恢复；代价是未捕获 InternalError 不能精确断言为栈耗尽，使用安全执行失败。取消、期限、已知资源和宿主失败仍为终止状态。
6. 为兼容广州脚本，接受经过初始目标校验的 Host 后丢弃，由传输层每跳生成；代价是增加 authority 解析和重定向测试，禁止脚本借此覆盖路由。
7. 上述 Host 进一步允许省略端口，比较时使用 URI 端口；显式端口仍须相符。代价是区分“省略端口”和“显式默认端口”的额外校验，已增加回归。
8. 按错误需求补齐每次解析的关联 ID、固定阶段/归属和非重试 HTTP403；代价是增加少量公开诊断字段和测试，不从任意异常正文猜 DNS 原因。
