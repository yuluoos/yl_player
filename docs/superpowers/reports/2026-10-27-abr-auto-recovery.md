# iOS 自动恢复、退避预算和连续性验证

基线 `5c104728`，当前分支 `codex/abr-recovery`。本轮按用户要求完善同源替换恢复候选，统一测试、保留失败、不放宽门槛、不发布。前两轮报告和原始记录保持不变：[原因排查](2026-10-27-abr-recovery.md)、[同源替换验证](2026-10-27-abr-penalty-recovery.md)。

## 本轮完成和边界

在显式诊断入口增加了由近期下载证据驱动的 `auto-reload`，源级最多两次预约、500/1000 ms 退避、准备后资格复查、暂停票据撤销；它复用现有同源替换事务，未修改生产播放器策略。两次初始自动运行均在约 49 秒触发一次，重新选到高档并完整播放。暂停对照和复审后的最终运行结果见下表。

已修复三项确认的问题：未来离散缓冲不能算作当前位置连续缓冲；暂停撤销的票据不能因稍后 resume 重新有效；旧探针多余的 raster 读取未消费可能返回的 retained buffer。新帧泵通过已有 display callback 读取并消费 buffer，不再额外读取。

**当前证据仍不构成生产安全自动恢复/连续性验收通过。** 策略是针对自有 clear/static DASH、auto/无上限的候选；下载窗口不是独立链路容量测量，不能判断所有低档停留都异常。实际替换存在应用层帧发布间隔；没有声学音频、字幕时标或物理画面连续性证据。本轮没有把诊断策略自动接入用户会话。

## 自动触发和预算设计

原网络 profile SHA `4e4f256c59465f4a573d6ab1c48f7a7571294638025088d0cddba9325f5032ea`，原 120 秒 MPD SHA `1be00f4b713ecdcaf00a5744ba344b6973d67db764e3f4aa65bdf613da46ceb6`，启动顺序不变。没有修改恢复阶段带宽、媒体、峰值限制或验收门槛。

候选仅在有过高档、当前低档、有 downloadOverdue 历史、播放中且剩余至少 20 秒时考虑；当前位置连续缓冲至少 5 秒。两段连续 8 秒窗口，各至少三个新增请求，按新增媒体字节/新增传输时间计算的吞吐达到声明高档 764000 bit/s 的 1.25 倍。它不使用固定 35 秒触发或 -12889 私有错误码判定。上述数字是本轮预先记录的实验决策参数，不是新验收阈值，也不是通用网络可用容量保证。

预算在预约时扣除，两次延迟分别 500/1000 ms；取消、失败、首帧成功、新 item 都不返还。准备和安装串行；ticket 绑定 generation、唯一身份和有效期，提交时复查当前 item 和资格。`pause-first` 在第一张票据发出后主动暂停，两秒后恢复，分别记录取消和后续尝试。最终版本在暂停时显式销毁旧 ticket，即使 resume 早于准备完成也不能复活。

这是**重建操作预算**，不等于全部 HTTP 请求共享一个重试计数；每个准备请求仍有现有网络策略。生产接入还需与会话 generation、pause/seek/切轨/约束意图、凭据和请求预算统一。当前原生夹具限定了来源和模式，不能把模型中的 allowed 输入替代完整生产约束集成证明。

## 帧观测修复

`frameSamplingVersion=2` 使用独立约 16 ms MainActor task，在异步准备期间继续驱动 display callback，记录实际发布 buffer 数、宽度、item generation、播放位置/rate 和采样时间；最后取消并等待 pump 退出，再核对原始样本总帧数与主收据相等。

这修复了旧 250 ms 主循环在 await 准备时停止采样的问题。它仍可能被主线程阻塞，故同时报告 pump 间隔与发布间隔。发布宽度来自实际 buffer；这些证据不等于物理屏幕显示或音频输出。新旧版本帧数量和采样空档不可直接横比。旧日志不回写为新协议通过。

auto / auto-repeat 的旧 item 最后一帧到新 item 第一帧发布间隔分别 223.311 / 327.480 ms，两侧媒体位置增量约 0.001696 / 0.007682 秒。位置没有倒退不代表墙钟连续播放；它显示替换边界确实存在帧发布停顿。不能称无缝，也不能把它和历史主循环 await 空档混为一谈。暂停对照的全程最大间隔包含人为两秒暂停，应与替换边界单列。
