# 小米电视 DASH 停供恢复与分段切换复测

在小米 MiTV-MTTP0（Android 9 / API 28，32 位）上，默认网络策略通过 25 秒停供恢复和持续停供两项验证。AVC 分辨率切换的三轮首帧及跨段间隔均在限值内。AVC → HEVC 和起播首帧的冻结指标仍有超限。[上轮同机数据](2026-11-22-android-mitv-decoder-and-playback-retest.md) · [本轮各次结果与构建哈希](evidence/2026-11-22-android-mitv-dash-recovery-and-transitions/results.json)

## 默认网络策略

素材是同一份 40 秒静态 DASH。以第一次 GET 为网络曲线起点，第 5 秒起停止发送响应体。恢复组在第 30 秒恢复，持续组直到错误上报都保持停供。每一轮分别启动服务并核对安装包、素材及网络曲线哈希。

| 最终代码真机结果 | 停供 25 秒 | 持续停供 |
| --- | ---: | ---: |
| 停供阶段媒体字节 | 0 | 0 |
| 缓冲采样数 | 87 | 161 |
| 终态 | completed | network.read_timeout |
| 结束位置 | 40.000 秒 | 2.851 秒 |
| 播放器清理及 ADB 端口解除 | 完成 | 完成 |

上轮默认策略在媒体位置 2.856 秒报错。首帧后的缓冲原来与起播共用一个读超时。现在，对于默认网络策略下的非 DRM DASH 点播，缓冲看门狗按 Media3 媒体加载器的尝试次数设置单个截止时间，默认 60 秒。起播仍用一个读取周期。持续停供时，最终 APK 从首次观测到缓冲至终态约 40.49 秒，传输层先返回了读取超时。两组独立构建均完成了恢复与错误清理。[网络语义](../../policies.md)

## 单解码器切换

电视在第一段只看到 320×180 的 AVC 格式。上轮切入 640×360 时，Media3 记录丢弃原解码器的原因为尺寸和输入容量不足（320 = 256 + 64）。现在从已解析清单查找相邻下一段的实际 AVC 格式，仅在此型号上为单一、设备支持的标清轨预留容量。Media3 保留兼容性判断。下一段大于 720×576 或编码不同会沿用常规路径。

| 最终包，每项三轮 | 首帧绝对音画偏差（ms） | 最大跨段间隔超额（ms） | 解码器结果 |
| --- | --- | ---: | --- |
| AVC 320×180 → AVC 640×360 | 16.490、19.711、20.657 | 8.333 | 三轮均复用 |
| AVC → HEVC | 190.128、166.188、199.274 | 206.298 | 三轮均重新初始化 |

最终包按原有 5 组 × 3 轮完成，1,514 个输出帧全部配到音频时钟。冻结门槛为绝对偏差 ≤70 ms、跨段间隔超额 ≤100 ms。全组最大绝对偏差为 199.274 ms。AVC → HEVC 时，新解码器初始化耗时为 152–157 ms。公开 Flutter 跨段套件 19 项通过，包含轨道切换、画面尺寸和节目结束位置。[冻结门槛](../../../tool/dash_timeline/joint_acceptance.json)

起播时，15/15 轮在首帧元数据回调和像素采样后的读数都为 0。首帧的请求释放时刻早于音频 sink 开始播放。按既有 1× 公式回推，12/15 轮的首帧超出 70 ms。新增的时序摘要保留两次时钟读数、音频开始播放时刻和冻结外推结果。起播以后的超限帧共 3 个，均是 1.5 秒处的跨编码首帧，在元数据回调时已落后音频。

## 真机对照

提前 200 ms 提交视频帧的试验中，纹理取样开始时间比请求显示时间早约 191 ms（中位数）。考虑到 Flutter 纹理可能提前消费，最终包使用原有的帧调度。强制异步编解码队列的三轮跨编码首帧绝对偏差为 178.939、200.749、191.634 ms；最终包使用原有队列策略。四批原生观测及每批失败门槛的退出码均纳入归档。

Android JVM 共 638 项，635 项通过，3 项跳过。主机 DASH 时间轴 20 项及弱网采集器 60 项通过。归档含 APK 安装哈希、JUnit 回执、网络分阶段字节、全部逐帧行与逐轮时序。归档 SHA-256 为 `9051eb2178acb8774351ea676bf40f81120333f66aef30e396a758ecf36a785f`。[下载原始采样](evidence/2026-11-22-android-mitv-dash-recovery-and-transitions/captures.tar.xz)
