# DASH 多档位与 tvs 直播接入

依据[实施计划](../plans/2026-09-24-dash-variants-and-live-integration.md)。播放器基线 `2b24d93`，业务项目 tvs 基线 `82ed28f`。本轮修改尚未提交；业务功能分支为 `codex/live-script-rtmp-integration`。三项实现、定向验证、独立任务复审及整批复审已完成。整批发现的三处 tvs 问题经一次集中修复和一次增量复审，均已解决，无剩余阻塞项；签收仅限本报告的阶段范围。

## Apple DASH 多档位

静态 AVC/AAC fMP4 子集由单视频档位扩展为兼容梯度：每 Period 最多16个视频 Representation，全文最多256个 Representation（包含音频），原有总段数、URI 和私有清单预算继续累积。各档位共享编码/角色并精确对齐段边界，跨 Period 按尺寸/码率/格式匹配，允许 ID 和 XML 顺序变化；一个可选 AAC 音轨共享。单档位原有语义保留。

每档生成完整节目时间轴的私有 HLS playlist，交给 AVPlayer 自动选择；所有初始化段和媒体段保留原代理与来源凭据规则。梯度增删、混合编码、显式未支持色彩/动态范围描述及不对齐分段仍拒绝。未增加固定档位接口，未声称强制清晰度上限或检查任意媒体位流的 HDR 一致性。

验证：macOS/iOS Simulator 各45项 compiler/loader 回归通过，均无失败或跳过；两端公开 Flutter 播放用例各1项通过。夹具为独立编码的320×180及640×360视频和共享AAC，两个4秒Period的ID/顺序不同。两端实际选择低档，匹配会话的首帧、自然跨Period、双向seek及播完均通过，最终位置分别8006/8018ms。没有观察到高档选择或弱网自动升降档，因此不将这些用例计作完整 ABR 验收。

证据位于 `/private/tmp/yl-dash-variants-macos-final.xcresult`、`yl-dash-variants-ios-final.xcresult` 及同目录 `yl-dash-variants-play-macos.log`、`yl-dash-variants-play-ios.log`。保留既有 Swift Sendable/链接警告；macOS 置前辅助命令返回1，但实际渲染断言通过。原生 xcresult 的 runtimeWarnings 均为空，不据此推断长期性能。

## tvs 业务接入

用户提供 `/Users/yy2021_8689/Desktop/GIt/tvs`，已定位原先直接跳过脚本和 RTMP 的业务入口。接入使用独立本地 resolver，并将解析得到的完整 `YlNetworkSource` 交给内核，保留自定义请求头的来源凭据语义与 live intent；不将其降为业务代理的普通 HTTP 请求头。直接 RTMP 绕过 HTTP 代理及默认请求头。

脚本解析任务由业务播放器持有，切台、停止、释放均等待真实解析/网络取消；会话代际检查也覆盖异步原生控制器创建后的加载入口。显式重播与允许的 HTTP 运行期恢复重新解析原始脚本引用，不把旧签名地址当永久源。直接与脚本解析出的 RTMP 都不再由业务层反复重开同源来重置内核重试额度，已有备用源顺序保留。

启动及运行期错误提示保留已知安全分类与关联ID，未知异常使用固定文案；汇总只记录本次实际源序号与原因，最多保留8条并报告省略数。原始URI、脚本参数和原生任意错误正文不进入日志。解析源绕过业务代理后，流量计量显示为不可用，不伪报零流量；这些源也不使用业务代理的高度降级候选。普通HTTP输入原有代理、重连与高度降级逻辑保留。

业务仓库最终6个目标测试文件共 **93项通过**，包含24项新增解析/接入用例；`flutter analyze --no-pub` 无问题，build_runner同步及diff检查通过。测试实际执行QuickJS原生代码资产与受控本机脚本/宿主请求，覆盖取消、刷新、HTTP凭据及RTMP交接；媒体播放平台为测试替身，不能将其视为 tvs 实际画面验收。修复前分别观察到RTMP被无条件跳过、结构化错误被压成通用提示、停止后异步工厂仍触发load/play的失败。

直接源仍沿用现有 proxy service 初始化流程；该辅助服务初始化失败仍可能阻止播放，本轮未做完整生命周期解耦。

整批复审发现并集中修复三处边界问题：脚本刷新由 HTTP 变为 RTMP 后，每次重开前重新判断协议许可；解开真实 `MediaStartupFailure` 包装以保留结构化原因；断连提示不再无依据地声称恢复次数耗尽。新增7项回归中，旧实现6项按预期失败、1项既有提示守护通过，修复后并入93项目标测试全部通过。静态分析首次发现新增测试一处括号样式提示，修正后仅重跑分析通过。

没有执行完整 tvs 应用原生构建、设备启动、真实 RTMP 对端播放或第三方订阅访问。保留现有插件SPM支持提示及build_runner的弃用参数/分析器版本警告，未为消除提示升级依赖。受控测试不等于用户订阅中全部真实频道可播放。

## 产品决定与剩余范围

用户已确认 PD-01：下一 Period 缺少固定档位时自动回到自动清晰度，允许降低到可用档位，见[ADR 0007](../../adr/0007-missing-fixed-quality-returns-to-auto.md)。本轮记录该决定并扩展自动多档位基础；完整固定控制接口及跨段档位缺失的运行行为尚未实现。PD-02/03、字幕、DRM、完整杜比、性能与扩展设备验收继续保留。

实施取舍及代价：

1. 先实现兼容自动梯度并接入已有 JS/RTMP 内核；代价是本轮不完成固定档位接口与完整 CAP-ABR。
2. 脚本结果保留完整来源凭据交给内核；代价是这些源绕过业务 HTTP 代理的流量计量与高度降级候选，部分原生不支持的路由/策略会明确失败。
3. 多档位增加16/256的 Representation 上限；代价是超大但有效的梯度需后续单独验证后才能放开。
4. 暂不扩展 AVC 中矛盾音频元数据的严格 schema 检查；未发现受支持有效梯度被错配的证据，但畸形元数据的准入仍可能不一致，需后续专门用例。
5. 保留 tvs 现有代理服务初始化生命周期；代价是代理初始化失败仍可能阻止直接 RTMP 或解析源播放。
