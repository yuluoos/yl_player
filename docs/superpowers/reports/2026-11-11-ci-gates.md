## 针对实际失败的修复

提交 `5850e428`，分支 `codex/ci-gates-20261111`：

1. foundation 显式安装 FFmpeg（包含 `ffprobe`）和 GnuPG，并输出工具版本。
   不依赖 runner 镜像偶然预装，也不将缺工具改成跳过测试。
2. 创建 Android AVD 前显式安装 platform-tools、emulator 和所选 API system image。
   API 24 原始失败为 `"emulator" package must be installed!`。
3. Android 集成入口固定 `--reporter expanded`。GitHub 默认 reporter 会缓存测试
   print 消息直到测试完成，而音频后台测试等待主机读到标记后发送 HOME，形成互等。
   既有超时、暂停位置不变及前台恢复断言全部保留。

两个回归用例先在原实现失败，再随修复通过。37 项 Android 脚本、进程边界、CI
调度回归通过。首轮沙箱执行受 `ps` 权限限制；重跑在允许检查测试自有进程的环境
中通过，原失败日志保留。安装工具后，DASH 素材 8 项检查全部通过；尝试整个
DASH timeline 套件时另外 3 项因本机 FlutterMacOS framework 缺失而失败，
不能将 8 项定向通过称为整套通过。YAML 解析及 `git diff --check` 通过。

另用本机真实 Dart 3.13.7 / test 1.31.1 做了隔离对照实验：同一个测试打印标记后
等待主机回执，在 `GITHUB_ACTIONS=true` 下默认报告器失败（exit 1），显式
expanded 通过（exit 0）。该实验验证报告器与主机的互等机制，不替代 Android
设备上的生命周期验收；源码、依赖锁与两份日志均归档在 `reporter-probe/`。

## 门禁继续执行后发现的问题

首轮修复 CI 的 API 36 集成测试成功；API 24 模拟器启动成功，音频后台/前台
和严格硬解拒绝两项通过，但普通 progressive 视频 load 报
`decoder.unavailable`，该 shard 仍失败。附件 SHA-256 与 GitHub 公布值匹配。
日志显示音频 AAC 解码已初始化，视频失败发生在公开 load 提交前；还不能据此
把视频播放判为通过，也没有将软件解码冒充硬件解码或跳过测试。

Apple unit 在运行用例前发现共享测试副本落后于现有 iOS/macOS 用例。
把两项既有回归同步到消费者共享 fixture，并把精确用例数更新为 iOS 909、
macOS 962；没有删除测试或放宽断言。历史来源/当前目标迁移检查 4 项通过，
runtime evidence 检查 9 项通过、1 项环境限定跳过。

foundation 的 DASH timeline 全部 20 项已在远端通过，继续执行时遇到独立
音频 tap Swift 编译失败。针对新旧 SDK 导入的直接/Unmanaged 所有权签名，
加入按实际函数类型选择的适配，保留编译 stderr 并使用测试临时模块缓存。
本机 5 项测试通过：3 项原有 PCM 证据检查，以及直接/旧式两条输出路径均仅
释放一次的实际 MediaToolbox tap 检查。新远端运行确认旧 SDK 编译通过，两个
所有权测试也通过；原有非空 PCM 测试在输出 JSON 时出现 `__SwiftValue` 崩溃，
已将可选标量先收敛到明确 Int/Float，再输出 JSON 数字。本机 5 项再次通过。

Apple unit 继续构建后，在 `YlRtmpProtocolTests` 的长数组加法表达式上发生旧
Swift 类型推断超时。改为明确的 Data append，并同步共享/iOS/macOS 三处副本，
生成的 36 字节与原表达式完全一致；迁移校验 4 项通过，用例和断言不变。
这两项测试兼容修复和收尾优化提交为 `256f85d1`。

首轮 CI 取消后，quick-aggregate 仍以 always 条件启动，下载整库耗时 8m48s，
阻塞新运行。改为仅在工作流未取消时汇总，并仅检出汇总脚本、设置 10 分钟上限。
正常失败仍进入汇总并拒绝通过；11 项既有汇总门禁测试通过。
