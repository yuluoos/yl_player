## 双会话与 HTTP

严格缓冲策略在候选源收到请求前返回 `policy.unsupported`，保留了当前会话。默认策略下，两会话的目标各为 24 MiB。候选加载期间，当前会话已分配 0 字节。候选会话在收到媒体前为 0，收到私有前缀后为 262,144，提交后为 1,048,576。原会话再次播放返回 `session.stale`。这些数字是 Media3 分配器在阶段边界的读数。

测试源在第三次请求的正文中断开连接，前两次为正常的文件头和尾部索引读取。下一次请求携带强 ETag 的 `If-Range`，以 `bytes=263069-10691178` 精确恢复一次，收到 206。跳至 14 秒后同一会话继续推进。原始计数为 `total=5 resumes=1 offset=263069 afterSeekMs=14622`。较早采集将正常尾部预读当成续传，随后又只匹配开放式 Range。最终断言校验实际中断位置、请求顺序及完整区间。

403 用例检查公开错误和异常，确认携带的请求头、凭据、地址与查询值没有出现在诊断中。随后新源可播。8193 像素宽的 PGS 被拒后视频继续推进。指定缺失字体的 ASS 经真机现用字幕绘制器读回 309 个红色字形像素，同一会话可恢复播放。这里记录的是离屏像素读回。

## TVS 直播与重试修复

- 旧款 MStar AVC 解码器在隧道模式下直接换 Surface 失败。RTMP 第四次断线后，用户手动重播曾因平台视图释放异常而等不到首帧。现在 API 28 及以下对这一具体解码器和隧道模式重建输出。最终回归中，三次断线均恢复原会话，第四次耗尽预算且连接数不再增加。手动重播成功创建新会话。
- 十个受控 HLS 源都返回 403。修复前默认加载策略对每个源请求四次，修复后按序各请求一次。TVS 显示前八项的有序错误及关联标识，并提示另有两次失败。503 的重试延时仍与 Media3 默认策略相同，另有 JVM 回归覆盖。
- 订阅刷新返回 HTML 或空 M3U 时，已保存的频道数据及当前会话均保留。有效刷新、脚本延迟返回期间换台和停止均通过。最终对端接受 16 个连接，关闭 16 个，结束时活动连接为 0。播放器和异步提供方均完成清理。设备 logcat 截断长 JSON，完成及清理标志取自完整字段，阶段从各自独立的日志记录核对。

## 设备收尾与验收范围

首次使用 Flutter 运行消费端时，多架构 APK 因电视空间不足未能安装。验收前系统列有 TVS 原包。后续核对时已消失。Flutter 首次构建前可按 Gradle namespace 识别应用，集成测试退出又默认卸载，这是最可能的原因。之后通过 Gradle 生成独立包 `com.example.tvs.ylacceptance`，按实际 applicationId 安装、启动及清理。复现时先构建并核验隔离包名。若使用 Flutter 测试命令，显式传入 `--no-uninstall` 并核对命名空间。

用户确认后已重新安装 TVS 1.2.7 正式 APK（versionCode 10012）。设备包 SHA-256 与本机一致，为 `86f6a60a3e0ae4b79f14a44bb1e0a056def7deeb8394d754e0b53d8a70f866f6`，主界面启动成功。先前安装的版本和原用户数据均无法核实。因存储不足，期间暂移本轮播放器示例测试包。收尾时已按 SHA-256 恢复示例 APK，以及示例包内的 232 份格式回执文件。独立验收包与三个测试端口转发已清理。

Android JVM 测试 647 项，跳过 3 项，失败与错误均为零。三个 Dart 测试相关文件静态分析通过。电视当时只枚举到内置扬声器。外接音频切换、受保护 HDR/Dolby 物理输出和外部音画时延仍需对应设备或素材。API 24 最低版本、九份冻结脚本原件、其他消费端及平台保留各自的验收记录。
