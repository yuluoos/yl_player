# 小米电视跨段选轨、字幕合成与片尾回跳验收

小米 MiTV-MTTP0（Android 9 / API 28，32 位）在三个公开播放器入口通过 7 项用例。使用各入口的 Debug APK，逐次核对已安装 APK 的 SHA-256。四种字幕在 1920×1080 系统合成画面上完成 24 次检查。[逐点数据、安装回执及源码哈希](evidence/2026-11-22-android-mitv-track-and-subtitle/results.json) · [原始截图、日志和失败对照](evidence/2026-11-22-android-mitv-track-and-subtitle/captures.tar.xz)

| 真机场景 | 观测 |
| --- | --- |
| DASH 跨段保留固定画质 | 两段轨道顺序不同，已固定的 360p 在第 2 段继续生效。服务端收到 4 个该段高档分片请求，播放至 8.000 秒片尾。 |
| DASH 下一段缺少高档 | 修复后复跑首次报告自动回退在 4.022 秒，原因是 `trackUnavailable`，分辨率为 180p。第 2 段低档收到 8 次分片请求。暂停、跳至 5 秒后继续前进，未再请求该段高档。 |
| WebVTT、TTML、WVTT、STPP | 每种格式检查 0.5、2.5、4.5、5.5、7.5 秒及停在 7.5 秒关闭字幕。实测背景依次为红、蓝、黑、黄、品红、品红。16 个有字幕观察在字幕矩形中检出 318–2687 个白色像素；间隙与关闭后的 8 个观察均为 0。 |
| 已完成的本地 MP4 回跳 | 片尾暂停，再跳至 4 秒片尾保持 `completed`。跳回 1.500 秒后显示一条 SRT 字幕，状态为 `paused`，同一会话在接下来的 500 ms 内位移小于 100 ms。最终同一 APK 三次冷启动通过。 |

## 故障复现与修复

1. 旧视图在没有字幕时直接显示视频，有字幕时将视频移入新的 Stack，导致原生视图在字幕出现时被替换。最初的 Flutter 图层读回在四种格式的 0.5 秒位置均为黑色。在修复前改用系统抓屏，并让 Flutter 持续刷新，四种格式都仍然显示黑底和字幕。修复后视频一直挂在同一父节点，字幕作为相邻图层增删。[开启字幕的实机画面](evidence/2026-11-22-android-mitv-track-and-subtitle/cue-on.png) · [关闭字幕的实机画面](evidence/2026-11-22-android-mitv-track-and-subtitle/cue-off.png)
2. 本地文件播放结束并暂停后，再向 Media3 请求片尾位置会重新进入 `ready`。现在对已到片尾且已知时长的点播保留完成态。用户回跳至节目中间时，Media3 再次就绪会保留已播放会话的暂停态，字幕按落点恢复。
   此前一次真机复测在 500 ms 检查点仍报告缓冲，位置已是 1.500 秒，字幕已恢复。最终三轮保留原 500 ms 断言，每轮再检查 500 ms 位置稳定。这个结果不构成最坏响应时间保证。

3. 首次修复复测中，TTML 和 STPP 的字幕矩形覆盖了 Flutter 的 DEBUG 角标。间隙画面留有 606 个角标白像素。最终测试关闭示例页角标，继续要求间隙和关闭时旧字幕区域白色像素为零。电视截图通过 ADB 回环转发采集，每次确认示例窗口在前台。

Flutter 视图及受保护字幕组件回归 31/31。Android JVM 测试 644 项，641 项通过，3 项跳过。Dart 静态分析在两个既有 Material 导入上给出弃用提示。真机素材均为自有明文 SDR；受保护 HDR 字幕、外接输出和扬声器同步仍需对应素材与设备链路。
