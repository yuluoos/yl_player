# 音频引擎时钟阻塞隔离：实现与验收

本轮五项计划已执行，音频锁隔离及时间配对修复已提交，完整20分钟验收已完成；**严格长播门禁未通过，不准入**。最终长播系统显示层丢4帧，不能用零应用丢帧或零时钟过期替代系统指标。候选默认关闭，`productionAdmission=false`。剩余系统丢帧、一次短测释放超时，以及A5／R4限制见下文。

实现提交：`a7a0c3f`、`f8bc001`、`789dc79`、`158489c`、`28db954`、`005f324`、`7acd53b`。最终行为源码为`7acd53b`。本报告不重新认证`b357849`之前的历史实现。

## 已修复及证据边界

1. 旧显示worker同步读取AVAudioEngine，历史真实栈进入`GetAttachAndEngineLock`等待。现改为每会话一个串行采样者、10ms合并timer与单槽缓存；worker和候选主线程进度查询只读快照，不等待原生采样。阻塞注入测试证明视频供给与控制撤销不依赖读数返回。没有声称找到Apple内部锁拥有者。
2. 观测保留原生媒体位置／host配对、generation、rate及提交范围；读取前后复核控制版本和映射状态。暂停、seek、变速、设备失效及关闭先撤销许可，迟到观测不能复活旧状态。原生年龄和发布后年龄各限100ms；过期冻结供帧，只有真实音频EOF允许视频尾部走时。
3. 真实0.25倍速暂停seek发现TimePitch上游时间提前118–145ms。候选使用输出节点原生host，经`playerTime(forNodeTime:)`转换成原生AVAudioTime配对；传host-only时间避免混用输出44.1k与播放器48k采样域。入队、暂停及观测保持同域，旧路径getter不变。Apple说明该API用于节点／播放器时间域转换（[AVAudioPlayerNode](https://developer.apple.com/documentation/avfaudio/avaudioplayernode)）。没有用调用结束时刻伪造host。
4. 首次长播发现另一问题：例如原生配对位置135.256500s对应其原生host，而完成回调已报告135.274333s。旧`media >= playedPosition`比较不同观测时刻，连续拒绝新鲜配对，约125s后缓存过期。新增测试先RED，再仅删除这一跨时刻比较；保留读取前后所有并发保护，不把配对位置抬高到完成位置。最终长播没有再次出现过期。
5. 历史退出诊断显示Thread Performance Checker的RPAC显著放大dispose开销；仅本轮性能manifest移除RPAC并逐行验证未加载，Main Thread Checker和XCTest保留。最终长播dispose449ms，进程正常退出。原历史长播超时没有当时的完整栈，不声称其每一步均已同因证明。

50ms／3帧窗口、100ms门限、macOS最低12均未放宽；定时候选仅macOS14+可用。没有接入商业SDK，也没有改变iOS默认时钟路径。

## 保留的失败与未解问题

- 首次短测`short`：播放期系统722／丢0／损坏0，时钟过期0，dispose约152ms；但disposed和disposedLater仍计费92,944字节，3秒归零等待失败。该数值与一帧视频计费一致，没有捕获实际持有者，不能推断为系统renderer、pausedPixel或某一队列。只补充资源分类诊断后的`short-resource`、最终短测和最终长播均归零，不等于此偶发释放延迟已定位或修复。
- `long`与`long-mapping-probe`为定位时间配对拒绝而提前结束的失败运行，保留SIGINT／-15、原始行、临时探针diff和stdout；它们没有activeEnd或完整20分钟边界，不能计入长播通过。
- **最终4帧系统丢弃尚未定位具体时点及原因。** 正式协议只在首末读取系统指标，不能从逐秒应用计数反推出系统丢弃时刻；没有证据将其全部归因于音频锁、窗口操作、原生层校时或环境负载。下一次定位应先增加按秒系统指标和有限的校时／投递诊断，按新增丢帧区间关联时间，而非无假设重复正式长播。
- 测量前原Pro曾按用户授权临时关闭，Pro Max回归结束后为Shutdown；测量后检查时原Pro已Booted，助手未再次启动，恢复时点未知。保持其当前状态，保存设备回执；不能据此免除4帧失败或声称已建立环境因果。
- A5系统资源上界、R4物理音画输出、macOS12／Intel及未具备真机能力仍开放。最终长播证明本次新时钟保持新鲜和退出完成，不证明普遍零丢帧或物理同步。
