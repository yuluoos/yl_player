# iOS 同源替换末帧保留与当前验收

基线 `06fd55b4`，分支 `codex/abr-recovery`。继续已授权恢复研究；保留此前全部失败，不放宽门槛，不发布。此前完整证据见 [自动候选验证](2026-10-27-abr-auto-recovery.md)。原始记录与逐次命令见 [证据目录](evidence/2026-10-27-abr-frame-retention/)。

## 已确认的修复

`replaceActiveDash → resetOpenState → removeCurrentItem` 原先无条件清空已发布纹理。回归在原实现上失败：同源替换多清空一次；修复后通过。仅在同 URI、同请求意图/凭据上下文、相同请求头/凭据、相同 MPD 字节及有效地址、clear static DASH、auto/无上限、正在请求播放、已有首帧、无错误/片尾且无待完成 seek 时保留纹理。清屏条件改变，旧 item/observer/framePolicy 的撤销不变，新 generation 精确 seek 落地前仍不能发布新帧。

测试覆盖同源保留、同 URL 新会话、URI/MPD 变化、上限、固定档、seek、pause 八种情形，均检查 stop 清空。该行为不启用生产自动 ABR 策略。它不预热新 item，不消除解码/seek 等待，不把旧帧重新发布或计入新帧数；物理屏幕和声学输出仍未确认。

证据工具同时修复准备期归因：有 `elapsedAfter` 时，以安装调用完成时间判断后续高档，不能将开始异步准备后的任意高档归功于替换。逐帧摘要新增 generation 边界的发布间隔、播放器时钟差、纹理清空增量及完全无发布的 generation；旧文件没有清空计数时写 null，不回填零。播放器时钟差不是解码 buffer PTS 差。原主行的 width 是 AVPlayerItem geometry，真实 buffer 宽度以 frame-samples 为准。

从前两轮主行累计访问日志另做的 8 秒窗口推算均低于冻结门槛 `764000 × 1.25 = 955000 bit/s`。这些行与策略取样存在微小时序差，不冒充策略内部完整决策追踪；原始事件列表确实为空。服务器设定的 4 Mbit/s 不是端到端可用容量证明，保留吞吐、缓冲、剩余时间和两窗口条件，不为真机触发而降低门槛。

独立复审发现并修复证据校验 P2：非对象 JSONL 行可能绕过异常处理且错误写 passed；现在显式拒绝非法类型，并要求两份成功摘要。清理 proof、进程列表及可执行 URL 也验证类型，超时命令保存有界输出。离线复现和红/绿回归保留；修复后复审未发现新增阻断问题。

## 本轮结论与验收边界

已确认并修复严格同源替换时主动清空纹理的问题；模拟器三次候选替换均无清空，仍有约 265–305 ms 新帧发布空档。当前真机允许安装运行，所选 84 项通过；真实媒体既有自然恢复至片尾，也有未到片尾的停顿，自动候选在全部真机样本中均未触发。因此安全自动触发、退避预算与暂停撤销的真机运行覆盖仍未取得，不能把测试名称或采集回执当作路径覆盖。
