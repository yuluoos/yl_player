# OPPO DASH 起播与跨段首帧时序排查

2026-11-21，OPPO CPH2065（Android 12 / API 31）。播放器基于 `4df15c89`。同一诊断 APK 在冻结的 5 组素材上各运行 3 轮，另对两种受控条件各运行 3 轮。15 轮基准的原生颜色与帧元数据检查全部完成，1,524 个输出帧样本有 1,518 个配到音频消费时钟。原有严格门槛要求零缺失、已配对样本绝对偏差最多 70 ms，本机仍未通过。[逐轮结果](evidence/2026-11-21-android-oppo-dash-frame-timing/results.json) · [原始帧、事件与设备回执](evidence/2026-11-21-android-oppo-dash-frame-timing/captures.tar.xz) · [冻结门槛](../../../tool/dash_timeline/joint_acceptance.json)

## 起播首帧早于首次 PCM 写入

6/15 轮在视频时间零点读取音频消费时钟时得到空值。这 6 轮中，音频 sink 在首帧采样后 5.1–27.0 ms 才开始第一次 PCM 写入，21.5–43.5 ms 后首次观察到有效时钟。15 轮的首次写入前时钟都为空，首次写入均被接受，返回时消费位置均为 0。其余 9 轮在视频首帧采样时已能读到位置 0。这里的时间以设备单调时钟记录，参考点是应用读取首帧所配音频位置的时刻。

对照组沿用 independent-pto 的视频与音频字节，仅将本机服务的音频初始化响应体延迟 160 ms。3/3 轮均在首帧处观察到空值，有效时钟首次出现在首帧采样后 127.8–186.1 ms。直接观察将缺口定位到视频首帧与音频 sink 建立可读时钟的先后顺序。这里的有效值 0 表示时钟可读；实际扬声器起声时刻没有测量。[原生测量与对照入口](../../../packages/yl_player_android/android/src/androidTest/kotlin/dev/ylplayer/yl_player_android/YlDashJointInstrumentedTest.kt)

## 1.5 秒切换时解码器重建

| 第 2 个 Period 的视频 | 解码器路径 | 新解码器初始化 | 首帧绝对偏差，3 轮 |
| --- | --- | ---: | --- |
| AVC 320×180 → HEVC 640×360 | 释放 AVC，创建 HEVC | 63–70 ms | 74.612、75.125、75.690 ms |
| AVC 320×180 → AVC 640×360 | 释放并重建 AVC | 63–74 ms | 74.614、74.967、75.019 ms |
| AVC 320×180 → AVC 320×180（对照） | 原解码器直接复用 | 无二次初始化 | 9.028、16.895、20.636 ms |

两组超限场景均在 1.5 秒的新 Period 首帧复现。Media3 的复用判断为 NO；丢弃原因位掩码分别为 328 和 320，均包含最大输入大小和最大分辨率，跨编码组还包含 MIME 类型变化。原数据也包含旧解码器释放、新解码器初始化、播放器状态和实际纹理颜色。对照组保持相同的 1.5 秒边界和 24 fps 视频，3 轮复用判断均为直接复用。

- 受控服务器在首帧释放前 1.51–1.62 秒已经准备好第二段的首个视频媒体分段。该时间记录的是服务端响应准备完成。
- 新视频解码器初始化完成后，约 62–83 ms 才到新段首帧释放时刻。6 轮均在该帧附近进入 buffering，音频 sink 在首帧释放前约 43–60 ms 暂停，并在释放后约 2–4 ms 收到播放命令。
- 在 GPU 读取前，6 轮的视频帧元数据回调都已读到音频位置 1,578,666 µs，比该帧的 PTS 超前 78.666 ms。中心像素读取耗时 4.2–7.8 ms。按冻结方法将实际消费位置折算到请求释放时刻后，超限量集中在该首帧。6 轮下一张采到的画面均在 1,583,333 µs，此时绝对偏差已回到 16.960 ms 以内。

这将下一步优化范围收窄到解码器切换与恢复播放的首帧调度。仅降低 GPU 读回耗时无法消除在帧元数据回调中已观测到的偏差。诊断没有改动播放器调度，也没有用后续音频时钟回填起播空值。设备的物理音画偏差、其他设备上的复用策略和预热收益仍未测量。
