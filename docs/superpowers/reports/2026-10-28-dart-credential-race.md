# Dart 并发 Load 凭据竞争验收

基线 `8fee00f3`，分支 `codex/abr-recovery`。按用户优先级补齐真实Dart并发凭据竞争验证，沿用集中验收，不发布。[原始证据](evidence/2026-10-28-dart-credential-race/)保存各阶段源码、日志、网络时序与最终源码绑定。

## 本轮实现

新增独立并发集成测试及统一入口 `apple_dash_credential_acceptance_test.dart`；统一入口注册[上轮顺序失败合约](2026-10-28-ios-postcommit-failure.md)和本轮两项竞争，一次应用启动执行三项。调用真实Dart控制器、Pigeon与Apple播放器，双回环源只使用固定合成凭据，没有替换生产网络实现。

1. 旧Load的MPD先跨源、返回主源，再由服务器挂起响应；此时调用新Load。旧future必须在释放旧响应前以load.cancelled结束，新Load已经提交。迟到旧响应不能产生旧会话媒体请求或覆盖赢家状态。
2. 旧Load已经提交，但其初始化媒体跨源hop响应被挂起；新Load提交并完成自己的初始化跳转后，才释放旧响应。旧session的firstFrame与pause命令返回sessionStale，赢家的会话、状态及事件归属保持正确。

两个Load使用同一个根URL及相同媒体资源名、独立合成凭据和普通请求标记。逐请求核对根、初始化、跨源hop、返回主源及分片；普通header保留，跨源与返回请求不得携带Authorization、Cookie、X-Session。赢家首个init必须携带自己的凭据，跨源剥离后该资源再次请求不得恢复凭据；旧media场景首个init也须携带旧Load自己的凭据。

赢家第二分片的响应等待旧handler完成，之后必须真正出现新的第三分片请求，并携带winner-fixture，防止短素材已预取的进度掩盖后续凭据污染。完整时序须为赢家提交、旧响应释放、旧handler完成、新赢家请求；随后验证ready、首帧、至少500ms进度及pause可用。使用已有4秒有效视频片段，首帧与进度均来自公开API；不等同实际音画连续性或长素材高档恢复。旧响应可能因客户端已取消而无法送达，记录证明的是迟到响应释放/处理与新请求，不声称旧响应已被客户端接收。

## 失败与复审

初版静态分析因8项缺少花括号的lint信息退出1，已修正并保留原日志和当时源码。初版macOS两项通过，但独立综合复审发现P2：释放旧响应后仅等待进度，凭据记录可能全来自预取；另缺旧init的凭据断言。已增加第二分片门闩、旧handler完成后的新请求证明和旧init断言，复审后定向macOS两项再次通过。针对修正及统一入口的只读复核通过。复审前的通过结果与最终结果分开保存，不能当作最终加强合约的覆盖。

本轮没有复现需要修改生产代码的新缺陷，只新增验证并补齐测试盲区。所有历史失败保持原状，没有降低首帧、进度、凭据或ABR门槛。
