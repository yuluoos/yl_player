## 2. 已确认的产品需求

| 编号 | 需求与约束 | 验收入口 |
|---|---|---|
| REQ-01 | Android、iOS、macOS 同步纳入首轮交付和共同验收；产品使用系统 API 与开源方案，不接入商业 SDK。商业方案仅作调研参考，未授权采购 | 全部 CAP、REG |

| REQ-09 | SRT、WebVTT、TTML、ASS/SSA、PGS、VobSub；内嵌/外挂、切轨、开关、时间偏移；字体、定位、描边、动画及图形字幕合成列入具体效果验收 | CAP-SUB |
| REQ-10 | 容器 MP4/MOV、MKV/WebM、FLV、MPEG-TS/PS、AVI；视频 H.264/H.265、VP9、AV1；音频 AAC、MP3、AC-3/E-AC-3、DTS、FLAC、Opus、Vorbis。首轮不包含 WMV/WMA、RM/RMVB | CAP-FORMAT |
| REQ-11 | 硬解不可用时允许按设备、分辨率与帧率限制软解；强制硬解禁止软解；不解除固定清晰度及 HDR/Dolby 画质约束 | CAP-DECODE |

| REQ-13 | 错误尽量明确失败环节、已知原因和处理建议；未知原因如实说明；保留稳定标识、可重试性及关联信息，多源失败可追溯 | ERR、REG-DIAG |
| REQ-14 | 先测现状，再按平台/设备档位制定目标，交付首帧、拖动、切台、卡顿、同步、资源及持续播放优化前后对比 | 第 7 节 |

## 3. 支持与验收矩阵

### 3.1 记录方式

下表是必须展开的验收工作清单，不是已发布支持表。设计阶段为每项创建可执行行，必填字段为：

`CAP 子编号 → REQ → 平台/最低可用系统 → 设备及输出链路 → 媒体/脚本哈希 → 封装/编码/Profile → 策略组合 → 操作序列 → 阈值及预期事件 → 实现状态 → 验证状态 → 证据位置 → 补齐责任与阻塞解除条件`。

实现状态分为未核查、未实现、部分实现、已实现；验证状态分为未执行、外部条件缺失、通过、失败、跳过。未知不等于不支持，已实现不等于已验证，跳过不计通过。不得仅写“待定”而没有下一步核查或所需输入。

### 3.3 可行性核查门槛

先核查完整杜比映射/外接链路、DRM 受保护渲染、Apple DASH 路由等会改变架构的路径。产物包含系统/开源候选路径、已有证据、缺失证据、参考样本、无法满足的要求及影响范围。未通过的路径不得标为可行；已能独立推进的其他能力不因此停工。

完整杜比目标保持不变。现有受限 FEL 实验、元数据保留、一般 HDR 输出不能代表完整映射；缺少参考输出或可用链路时明确记录阻塞，不能使用商业 SDK、忽略元数据或基础层替代来满足验收。

## 5. 错误信息验收表

用户信息表达“失败环节 + 有证据的原因 + 可操作建议”，不虚构根因。[YlFailure](../../../packages/yl_player_platform_interface/lib/src/model/failure.dart)已有 category、code、message、retryable、scope、diagnosticId。下表“候选”错误码尚非现有 API，正式码表及桥接映射需在实现前冻结。

| 用例 | 触发条件 | 错误标识方向 | 提示示例 / 恢复要求 |
|---|---|---|---|
| ERR-01 | 订阅应为 M3U，实际返回 HTML | 候选 source.unexpected_content | “订阅返回网页，未获取到频道列表；请检查订阅地址或请求配置。”不宣称各地区均失效 |
| ERR-02 | 可确定 DNS 失败 | 候选 network.dns_failed | “播放源域名解析失败；请检查网络或更换线路。”不猜服务器关停；按预算决定重试 |
| ERR-03 | 收到 HTTP 403 | 候选 network.http_forbidden | “服务器拒绝请求（HTTP 403）；请检查访问权限或更新源配置。”不直接断言 token 过期，不反复重试同一拒绝 |
| ERR-04 | JS 超过已配置执行期限 | 候选 script.timeout | “直播源脚本执行超时。”终止任务并释放资源，不只是隐藏迟到结果却任其继续占用资源 |
| ERR-05 | 缺宿主接口 / 无有效播放地址 | 候选 script.host_api_unsupported / script.invalid_result | 区分“缺少脚本所需接口”和“脚本未返回有效播放地址”，不泛化成网络错误 |
| ERR-06 | RTMP 握手失败 / 播放中断 | 候选 network.rtmp_handshake_failed / network.rtmp_disconnected | 区分建立连接与传输中断，仅符合策略的瞬态故障尝试恢复 |
| ERR-07 | 明确许可证拒绝 / 失效 / 超时 | 候选 drm.license_denied / drm.license_expired / drm.license_timeout | 分别提示；普通 HTTP 失败不猜成许可证过期；不展示证书、请求体或密钥数据 |
| ERR-08 | 无可证明的必需硬解 / 软解超限 | 现有 decoder.unavailable / resource.exhausted，细分码待设计 | 说明编码/策略无法执行，不擅自软解或降低手动固定档位 |
| ERR-09 | 不支持的杜比 Profile / 显示元数据 | 沿用或细化既有杜比错误标识 | “当前播放路径不支持该杜比 Profile/显示元数据。”不误报损坏，不输出基础层假装成功 |
| ERR-10 | 字幕解析 / 字体或图形资源失败 | 候选 subtitle.parse_failed / subtitle.resource_unavailable | 明确字幕错误，恢复范围按 PD-03，不能误报视频解码失败 |
| ERR-11 | 同频道本次实际尝试的全部源失败或跳过 | 配套/业务层有界汇总，内核保留单次 YlFailure | “本次已尝试 N 个源，均未成功”；按序保留安全类别、原因及关联 ID，不只留最后一条 |
| ERR-12 | 取消/旧会话失效 / 未知异常 | 现有 load.cancelled、session.stale / 既有兜底码 | 用户取消不作为当前源故障弹窗；旧任务不覆盖新错误；未知故障说明阶段和关联 ID |

汇总只记录实际已发生的尝试，不授权新的自动换源策略。容量和截断规则在设计中固定，避免无限历史；受控用例验证 source=1/10 脚本跳过与 source=2/10 RTMP 跳过各有可追溯原因。错误归属解析模块、内核还是业务层必须可识别。

不透传带签名 URL、请求头、脚本任意文本或原生堆栈。retryable、scope 与 UI 提示须和实际恢复一致。

## 6. mytvJS 样本与兼容验证

冻结清单和完整 SHA-256 见 [访谈记录样本账本](2026-09-20-playback-expansion-intake.md)。2026-09-22 已恢复全部九份原始字节并核对哈希，完成三端受控执行与媒体交接；证据和可取回样本边界见 [JS 阶段报告](../reports/2026-09-22-script-resolver.md)。受控执行不代表外部订阅地址当前可播放。

兼容实现前，每脚本补齐：`版本哈希 → main 输入/频道参数 → 宿主调用 → 同步/异步语义 → 地址/请求头/错误/有效期返回 → 受控响应夹具 → 预期结果 → 三端证据`。CryptoJS、parseItems 等可见字符串只是调查线索，不能据此认定完整宿主契约。

逐脚本覆盖正常解析、缺失/非法参数、请求失败、畸形返回、超时、取消、过期刷新及旧任务迟到。没有显式有效期时标为未知，不从示例 token 猜通用期限；只为实际依赖的调用建立宿主适配。

冻结版本用于复现回归，远程最新版兼容观察单列；不能换样本来使失败消失。哈希、宿主契约或返回结构变化时新增版本并复测。正文和真实地址在受控样本位置管理，仓库只留标识、哈希和结论；长期归档的可取回性须在验收前验证。

## 7. 性能基线与指标冻结

### 7.1 冻结顺序

1. 优化前记录提交、未提交差异指纹、构建模式、依赖/原生制品版本；固定设备/OS、电源和热状态、屏幕/输出、媒体哈希、网络轨迹、缓存及脚本/许可证条件。
2. 先确认基线样本播放正确，再测已有路径。原先无法播放的新增能力标记“无可比基线”，单独制定绝对目标，不捏造改善百分比。
3. 形成带版本指标表：定义、平台/档位、样本、重复次数、允许失败数、p50/p95 或相应统计量、目标、不可退化阈值和证据位置。数值依据实测，在对应优化代码变更前冻结。
4. 相同条件重测。调整样本、目标或方法须说明原因、保留旧结果并重测受影响基线，不能只因不达标而放宽阈值；新的产品取舍需确认。

### 7.2 测量定义

| 指标 | 测量边界与报告要求 |
|---|---|
| 首帧 | 调用公共 Load 前立即读取单调时钟，至该次加载的 Session 首帧在公开输出呈现；不从 Load 返回、Ready 或解码结束开始计时。另测用户发起播放至首帧全链路，将 JS 解析、许可证与内核耗时分段 |
| 拖动恢复 | 调用 seek 前立即读取单调时钟，至目标附近首帧及稳定音画恢复；位置容差与稳定窗口先定义；取消的 seek 不混入成功样本 |
| 切台 | 业务端发起切台至新频道首帧；分报脚本解析、源尝试数、网络和内核耗时 |
| 卡顿 | 初始缓冲和再缓冲分开计次数/时长/比例；主动暂停和 seek 单列 |
| 音画/字幕同步 | 已知时标样本，报告误差分布及最大偏差；跨段、重连、seek 后单列 |
| CPU/内存/发热 | 报采样窗口、峰值/稳态；RSS、媒体账本、脚本堆和可观测 GPU 数据分开；记录热状态/可测温度，不将模拟器视作真机发热证据 |
| 长时间播放 | 持续时长、操作次数、故障轨迹预先固定；检查资源增长、停止释放、崩溃/挂起和恢复 |
| 直播延迟 | 有可信源时钟才报告源到显示延迟，否则只报实际测得的缓冲/追赶指标；协议和模式分组 |

冷/热启动与缓存命中分组，重复次数在采集前指定；样本不足以解释 p95 时说明限制。超时、失败、跳过单独计数，不静默从分母移除。优化后仍须通过功能正确性与 REG。
