# Apple DASH fixed rendition selection and missing-Period fallback

Continue the approved REQ-04/05/13 and ADR 0007 after runtime caps commit `f3b2cd3`. This is the Apple completion of the existing public `selectVideoTrack(String?)` contract, scoped to the already admitted compatible clear static AVC/AAC DASH domain. No commercial SDK, dependency, media-byte or deployment-floor change. The user already approved implementation and PD-01: missing fixed quality returns to automatic, permitting lower quality within remaining caps.

## Public contract

A non-null ID must identify a currently available, unambiguous video quality. Null returns to automatic. `YlVideoSelection(fixedTrackId, reason)` remains the single mode authority: initial automatic on new Load/Stop, user on explicit selection/clear, trackUnavailable after confirmed current-Period loss. Fallback is sticky: seek back, later reappearance and restoration do not silently re-enable fixed mode. Temporary empty metadata, buffering and bandwidth shortages are not missing-quality evidence. Every published fixed ID must occur in the same state's available catalog. Catalog remains all allowed qualities, not just the filtered media candidate; `isSelected` must not imply measured decoded bitrate.

Actual media projection enforces fixed quality, not AVPlayer preferred bitrate/resolution. During each Period where fixed mode is active and its semantic identity exists, every selectable media path must use that one identity. Matching ignores representation IDs and XML order and includes codec, dimensions, video bandwidth, normalized frame rate, roles and admitted range/pixel family. Reject ambiguous or incompatible selection with a stable safe command error, without broadening source admission. Existing declared catalog IDs may be retained where the strict admitted family proves uniqueness. Cross HDR/SDR remains outside this stage; PD-02 is not implicitly decided.

Fixed quality survives transport commands and mere buffering. On authority entering a Period without it, the mode becomes automatic/trackUnavailable, retaining caps, decoder and output policies. Prefetch of future Periods must not change current mode. Do not leave the player effectively pinned in earlier Periods after sticky fallback: all subsequent playback/seeks use the automatic projection. Prepare a dormant fully automatic candidate together with each accepted fixed projection, under the existing bounded loader budgets; do not activate output or fetch media for the dormant candidate. On authoritative absence, synchronously install that automatic candidate and commit sticky mode in the same main turn. Release it on replacement, Stop, disposal and deactivation; restoration recompiles the accepted policy and spare as needed. This avoids a window where the public automatic mode still uses fixed paths. An internal replacement may briefly buffer; its failure must be surfaced safely rather than claiming an effective auto policy that never installed. Resolve backward seeks into missing Periods and restoration using the same authoritative rule. Separate confirmed current position from a pending user/runtime seek target: while a fixed seek has not settled, retain the last coherent catalog/mode and gate frames that could contradict it. At successful guarded landing, use measured position to reconcile mode; a retired/cancelled seek cannot trigger fallback. The existing automatic-mode catalog behavior need not change. If the latest fixed seek completes unsuccessfully, perform at most one guarded recovery seek to the last confirmed position, bounded by a five-second deadline. A false recovery completion or timeout produces a safe `source.seek_failed` session failure instead of leaving playback silently gated forever. Newer seek, item replacement, Stop and disposal fence both completion and deadline.

## Transactions and lifecycle

Reuse the accepted original bounded MPD snapshot and effective URL/provenance, never refetch or compile from already reduced candidates. Reuse/extract the runtime cap transaction rather than create competing mutators. Explicit fixed/auto selection and constraints commands share supersession authority; equal-policy commands cancel obsolete work. Pending new Load wins. Stop, disposal, deactivate, lease quiescence and memory warning cancel work and release resources. Stale callbacks may neither publish nor change accepted policies/output.

The command Future awaits validation, preparation and installation/policy commit, not first frame; prepare failure retains old item, mode, caps, catalog, identity, position and output. At commit preserve exact latest measured position or unresolved explicit seek target, pause/rate/volume/audio intent. Reconcile a seek/Period change during preparation before claiming a fixed selection. Cap updates excluding the fixed identity reject rather than silently clearing fixed, including conflict across a Period where the fixed identity exists. Caps remain independent and every Period must retain an eligible automatic candidate.

Inactive/restoring changed selection explicitly fails with a safe command error (no acknowledged deferred policy); equal accepted mode may be a no-op. Deactivation/restoration preserves accepted mode or sticky fallback; new Load/Stop resets it. Ordinary HLS/MP4/fallback sources continue to reject fixed selection honestly. Capability can indicate the implemented operation at platform level with source restrictions documented and enforced.

## Wire and compatibility

Implement the existing optional Dart SPI selection interface in Apple. Add a nullable-ID async Pigeon command and full-state selection metadata; preserve selection in timeline deltas. Bump Apple wire schema 3 to 4 and reject old binaries before allocation. Append new message classes after existing ones to preserve old factory codec tags so mismatched old requests reach the schema gate. Keep SPI major 2 and all existing enum ordinals. Validate reason and fixed/catalog consistency, safely redact IDs/errors, use pinned generator and update relevant stubs/tests. No Android changes.
