# 音频引擎锁与定时视频供帧的阻塞隔离

状态：基于已批准的macOS定时显示候选，提出内部时钟读取架构修订，等待书面设计审阅；尚未实施。用户要求实施隔离并验证长播，继续在当前任务内执行。原有候选默认关闭、无商业SDK、最低系统版本、50ms/3帧窗口和100ms验收门限不变。

## 目标和依据

视频worker不能在逐帧路径调用可能等待AVAudioEngine内部锁的API，也不能通过无期限外推掩盖音频停顿。此前实际线程栈、受控复现和被中止的失败长播见[定位报告](../reports/2026-10-10-timed-presentation-followup.md)。需要消除的是同步依赖；系统整体失去调度或音频读数长时间不可用时，仍须明确失败，不能承诺任意负载下零卡顿。

新增短时静音原生探针证据：[audio-clock-timestamp-probe.json](../../../tool/playback_benchmark/audio-clock-timestamp-probe.json)。10次观测中，node和player的hostTime均有效且相同，其时间约在查询结束后15–24ms。该探针只验证本机rate=1的时间配对，不证明实际扬声器呈现。Apple的[playerTime(forNodeTime:)](https://developer.apple.com/documentation/avfaudio/avaudioplayernode/playertime%28fornodetime%3A%29)返回player时间；[player timeline文档](https://developer.apple.com/documentation/avfaudio/avaudioplayernode)说明pause和stop对时间线的影响。实现时还须验证暂停、变速及失效场景。

## 方案选择

| 方案 | 决定 |
| --- | --- |
| 视频worker继续同步读取，只减少读取频率或换成读完时刻 | 仍会阻塞；丢失原生采样时间，拒绝 |
| 在渲染回调中新增音频tap发布时钟 | 需改变音频图及实时线程工作，当前范围不采用 |
| 单一后台采样者发布有界、带时间戳与epoch的快照 | 推荐；worker只读标量状态，音频系统调用留在采样边界 |

仅对已启用macOS定时显示候选的会话使用新路径。旧显示路径、iOS、bounded、直播、AVPlayer后端保持原有行为。不能用旧路径回退后的成功结果冒充新候选通过。

## 数据与线程契约

1. 保留原生读数的sampleTime、sampleRate以及与其对应的hostTime。输出读取结果必须显式区分：可用、尚未有读数、暂停、实际音频结束、音频时钟失效。nil不能同时代表“采样阻塞中”和“没有音频”，否则会触发错误的host回退。
2. 在renderer的现有generation与播放区间约束内，将player时间映射到媒体时间；快照携带媒体位置、对应host时间、rate、已提交音频区间上下界、采样完成时刻、音频epoch和控制版本。不得把较旧读数与被其他回调推进后的playedPosition强行配成一个时间点。遇到这种竞争，丢弃不一致样本并重新采样。
3. 每个候选会话仅一个串行采样者、一个10ms合并timer和一个快照槽。一个原生调用未返回时，不能再追加逐tick任务或启动替代采样者。读取系统API时不持有session、renderer快照槽或视频worker的锁。
4. 视频worker与候选会话的逐帧位置读取只读已发布快照，不再自行调用lastRenderTime/playerTime。既有音频提交仍按真实音频队列需求运行；本次不宣称消除音频图自身的锁争用。
5. 采样取得与发布分离：开始前读取epoch/控制版本，返回后再次校验。flush、seek、rate、pause、reset、dispose或音频设备失效后的旧结果不得发布。视频worker的lease与generation校验继续执行。

## 时间换算与有效期

媒体位置与host时间必须来自同一有效观测。采用带符号的host差值进行换算；原生host时间略在未来时不能用max(0, delta)抹掉负差，且媒体位置不得越出快照对应的已提交音频区间。所有换算须检查有限数、正sampleRate与整数溢出。

正常运行每10ms刷新一次。发布槽只保留最新一份成功观测。快照有效期同时受以下条件限制：

- 自采样完成后最多100ms；
- 当前host与原生观测host的距离不超过100ms；
- epoch与控制版本仍相同，且音频区间未撤销。

100ms是失败检测上限，不能视为允许100ms音画误差的性能目标。正常音画偏差、原生校正幅度及读数年龄独立记录；通过标准不放宽。超过有效期时不继续外推、不使用nil触发host回退：停止新视频提交，将显示timebase固定在最后一个有效且受区间约束的位置，记录clockUnavailable/stale事件。恢复须取得新鲜同代快照，再同步timebase；恢复不能清零既有失败计数。启动尚未有样本时等待，超过100ms同样记失效。

真实音频结束后，只有renderer确认输入结束且播放队列排空，才允许既有视频尾部host回退。音频暂时欠载时使用已有停顿/静音区间逻辑，并保留明确状态；不能把“原生读取暂不可得”当结束。

## 控制与生命周期

| 事件 | 要求 |
| --- | --- |
| play/resume | 新控制版本；取得对应实际音频状态后开放提交，不沿用暂停前已过期样本 |
| pause | 控制命令生效即撤销旧运行快照，固定已确认位置；晚到采样无权恢复playing |
| rate | 先撤销旧版本，按同一媒体位置切换rate；测试0.25、1、2、4倍速，不用旧速率外推新时间线 |
| seek/reset/换源 | 新epoch；清除快照及采样资格；旧系统调用返回后仅丢弃，不影响新画面 |
| detach/reattach | 沿用endpoint撤销；离屏不累积future帧；重附着验证当前epoch新鲜度 |
| device change/音频图失效 | 立即废止样本并保留原有音频错误，不继续伪造走时 |
| close | 立即撤销发布与视频提交；取消timer，不在视频队列或main等待采样者；延迟调用完成后自行释放，不能开启新的采样者链 |

采样者不可通过持有完整会话形成循环引用。不得为每次seek保留一个后台阻塞任务；同一会话复用单一采样者，换epoch只更新许可。现有音频引擎停止/释放可能仍执行系统同步调用，其延迟另测，不能因视频隔离成功而宣称退出阻塞全部解决。

## 可观察性和失败门禁

记录：真实候选使用、采样次数、原生读耗时最大值、快照年龄最大值、过期次数、旧代结果拒绝次数、worker最大空档、系统帧指标、应用丢帧、音频欠载、资源与退出阶段。应有的字段缺失即无法验收；过期次数非零不得算长播通过。旧代拒绝属于正常控制隔离，按测试场景单列，不混作系统丢帧。

诊断开关不会改变采样/有效期算法。Thread Performance Checker仅在复制的性能测试manifest中排除，并验证运行时确实未加载；日常功能检查不全局关闭。所有失败、用户环境干预、进程清理和源/二进制身份均保留。

## 验证顺序与完成标准

先写失败测试，再实现本设计；工作在当前任务内连续执行。

1. 可控原生reader阻塞时，已就绪的视频仍可使用有效快照供给；阻塞超过100ms必须明确过期、停止外推且不积压任务。释放后恢复，不清除失败证据。
2. 用字面量验证真实host时间配对、未来host的负差、区间上下界、rate、EOF回退、欠载、非法值与溢出。用屏障验证pause/seek/rate/dispose期间的晚到读数无权覆盖新状态。
3. 真实音频图验证有效时间戳、pause/resume、变速、reset及设备错误；真实显示层验证现有250ms main阻塞仍可连续供帧、暂停像素和seek代际隔离。
4. 集中运行受影响的macOS时钟/音频/生命周期回归；若共享默认行为发生变化，补iPhone18 Pro Max对应回归。保持真实测试通过与硬件条件跳过分开。
5. 冻结源码/二进制后先做短时外部激活，再做一次20分钟Profile真实显示长播。先检查测试环境；不中断未获授权的其他工作。记录窗口可见性与全机负载，发生干预仍保留失败，不把环境相关样本静默排除。
6. 通过须同时满足：活动系统/应用零新增丢帧、系统指标有效、worker空档和既有时延门限合格、无快照过期、真实候选启用、暂停像素有效、资源归零及所属进程正常退出。否则继续定位或给出明确不准入结论，不能把实施完成等同于长播已修复。

设计中的阻塞隔离不等于操作系统实时调度保证。A5系统整体资源上界、R4物理音画验收继续开放；本机通过也不自动打开生产默认开关。
