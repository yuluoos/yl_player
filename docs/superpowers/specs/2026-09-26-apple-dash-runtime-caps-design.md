## Transaction contract

The command Future completes after validation, bounded preparation and the same-main-turn item installation/accepted-policy commit. It does not promise that a new decoded frame has arrived: post-commit network/decoder failures retain ordinary playback error semantics, as with Load. Preparation failure/cancellation must leave the old AV item, measured progress, session identity, catalog, accepted constraints, playback intent and output untouched. No transient candidate state or error may replace the accepted state before commit. Brief rebuffering during successful item replacement is permitted; do not claim seamless switching or decoder-failure rollback after commit.

Preparation recompiles a bounded snapshot of the **accepted original MPD bytes and effective root URL**, including its source credential provenance, under the requested caps. Do not refetch the MPD: loosening caps must recover original representations rather than re-filtering the currently reduced presentation, and program/timeline changes at the server must not alter an existing session. Snapshot exists only after successful admission, is copied immutably and cleared from canceled loader ownership; installed ownership may preserve it for restoration just like the catalog. Preserve all budgets, credential stripping, private namespace isolation, strict family checks and video bitrate semantics. Never expose bytes/URLs/credentials in public errors or track IDs.

At commit sample the current backend's exact measured time and current play/pause intent, not command-start state. If the latest acknowledged user seek has not landed yet, transfer that generation-scoped target into the replacement rather than canceling it by reverting to the old measured position; this exception is for replacement intent only, not optimistic ordinary timeline publication. Once its guarded seek completes, measured landing is authoritative. Preserve selected audio intent, volume and playback speed where the existing single-AAC domain permits. Install using the new loader projection, exact saved microseconds and current intent. Public session/load identity stays unchanged; catalog is the effective current-Period projection; all entries remain unselected and videoSelection automatic/initial. Existing actual-frame dimension checks must apply to the committed policy and retired callbacks must not publish or feed output. Accepted coordinator/backend policies change only at successful commit and later deactivation/restoration must preserve the new caps and original manifest snapshot.

A newer constraints request supersedes/cancels an earlier pending request, including a no-op equal to the accepted policy. Stop/dispose/new Load/deactivation/memory warning cancel pending work exactly once and release its resources. New Load has priority; a constraints request must not cancel an unrelated pending Load. Seek, pause, speed, volume while preparation is pending remain effective and the commit uses latest state. Inactive/restoring DASH changes may keep the existing explicit reload-required rejection in this stage; an equal accepted policy remains an idempotent no-op. This boundary must be documented/tested rather than silently retaining an unexecuted policy.
