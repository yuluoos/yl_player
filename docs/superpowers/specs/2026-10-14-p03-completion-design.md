本轮只读验证：`tool/media_matrix` 单测 8/8，catalog 验证通过。当前已提交 XCFramework 的原生调用显示，WebM/Vorbis 音轨 `ylf_stream_vorbis_preroll_us = -1`，零 delay 的 MKV/Vorbis 对照为 `200000`；二者都成功打开且均识别为 48 kHz 双声道 Vorbis。探针首次使用相对路径得到 InvalidArgument，改用 API 要求的绝对路径后获得上述结果；不将首次调用当成素材失败。

MPEG-2 是现有 MPEG-PS 探测夹具的编码，不属于 REQ-10 的四种视频编码承诺。新增 PS/AVC 行验证已确认容器能力；原 MPEG-2 行继续明确标注诊断用途及实际结果，不能删除它或把它改成成功。若 PS/AVC 在目标平台不成立，记录证据并继续处理 PS 播放缺口。

## 路线比较

| 路线 | 收益 | 代价及结论 |
| --- | --- | --- |
| 原生优先，复用裁剪 FFmpeg，增加 dav1d 软件 AV1 和内部解码资源接口 | 保留现有时钟、输出、网络、租约和错误契约；软件路径可独立计量、关闭和验证 | 需要新增开源源码锁、五目标制品与预算模块；推荐 |
| 只补 VT AV1，等待有硬件的设备 | 依赖增量小 | 无法处理当前 M1 上的 AV1，也未完成已确认的受控软解要求；作为硬件子路径，不能替代本轮目标 |
| 接入另一套完整播放器或完整 FFmpeg 构建 | 表面格式覆盖较广 | 重复网络、输出和策略责任，扩大制品及回归范围；不采用 |

dav1d 的项目资料说明其为跨平台 AV1 解码器，采用 BSD 2-Clause；FFmpeg 提供 libdav1d 适配。选择它是架构方案，不是本项目性能已达标的证据。依赖版本和源码摘要在候选构建前锁定，并经过完整重建核验。[VideoLAN 项目](https://images.videolan.org/projects/dav1d.html)、[官方源码镜像](https://github.com/videolan/dav1d)、[FFmpeg 适配源码](https://www.ffmpeg.org/doxygen/8.0/libdav1d_8c_source.html)。

## 解码资源接口与数据流

1. **探测与描述**：媒体字节决定容器；声明和扩展名只是线索。配置携带 codec、profile、位深、chroma、尺寸、帧率/时基、色彩、动态范围、重排/参考约束。无法确定安全上界的输入不进入软件候选。
2. **策略与准备**：先核查输出兼容性、固定画质及 HDR/Dolby 约束，再尝试原生硬件。`hardwareRequired` 从不准备软件候选；每次创建、seek/Period 重建、恢复都验证实际硬件属性。提示值或未知属性不能冒充证据。
3. **内部资源抽象**：将 `YlVideoPipeline` 的普通 VT 资源背后的提交、drain、reset、invalidate、模式证据和输出回调统一为内部接口。现有 FEL 资源继续保持完整独立处理，不通过普通软件 decoder 丢掉增强层或元数据。Dart 公共 decoder policy 不新增枚举。
4. **软件桥接**：新增受限的包输入、帧输出和所有权接口；初始 AV1 面向 Main 8/10-bit 420，VP9 扩展按实际夹具分项开启。AV1 使用固定 dav1d；需要的 VP9 软件路径使用裁剪 FFmpeg decoder。无对应组合证据的其他软件 decoder 不因依赖可编译而自动启用。
5. **输出**：软件帧转成现有输出可接受的像素缓冲，明确 plane stride、位深、范围、色彩附件及 PTS。禁止将 10-bit/HDR 静默转成 8-bit/SDR。保留 film grain 等影响正常画面的解码语义；不以关闭这些特性换取预算通过。
6. **代际和释放**：复用 session/seek/Period generation，旧候选或迟到帧只释放不呈现。drain 输出尾帧；seek 清除重排队列与计量，重新建立参考状态。取消能终止后续提交，释放等待仍有界；不可取消的单次原生 decode 必须受输入大小与已准入复杂度约束，不能声称超时能抢占 C 调用。
7. **共享资源**：当前与候选 decoder 同时存在的成本均计入进程级软件准入租约；失败准备归还所有预留。多个播放器不能各自使用完整进程预算。硬件租约、网络 buffer ledger 和软件计算预算保留各自语义。

AV1 硬件路线与软件路线使用同一配置校验，实际结果分别标为 hardware/software。AVC/HEVC 现有 VT 软件返回也需经软件准入检查，不因 codec 已有支持而免除预算。Android 保留 Media3/native 两条路线，在选择、实际 decoder 身份与重建边界补相同语义；不改弱网选档算法来掩盖解码失败。

## 软件准入与测量依赖

新增内部 `SoftwareDecodeProfile` 与 `DecodeResourceBudget`，不先增加面向调用方的可调性能开关。Profile 键至少包含平台、硬件族/型号、OS 有效范围、codec/profile、位深/chroma、尺寸/fps 上限、线程数、输出路径和构建身份；配置与证据摘要绑定。模拟器、未知设备或未测组合没有生产准入记录。

预算使用明确单位：owned bytes、解码/重排/待呈现帧数、窗口内 CPU 时间、解码墙钟时间及系统热状态。分配前检查尺寸乘法溢出、压缩包/头大小、参考帧与输出池上界；实际拥有的帧、复制、暂存与候选重叠全部计数。decoder 内部不可直接归属的开销单列实测，不把 owned-memory 上界冒充全进程 RSS 上界。

测量流程：

1. 在 `tool/decoder_probe/` 新增独立的 P03 软件观测入口，复用 P08 的指标定义和有效性规则，不修改 `tool/playback_benchmark/` 的长播工具或报告。
2. 在运行前冻结媒体哈希、编译模式、codec/线程配置、重复次数、窗口、环境采样和失败处理。先取无软件候选的对照及软件候选原始数据；新增路径没有可比旧实现时明确注明。
3. 分别记录进程 CPU/RSS/footprint 与可归属 decoder 的时间/owned bytes。解码内部工作线程必须包含在计算计量中；无法正确归属时用保守进程上界并明确记录，不能只测外层提交线程。
4. 由合格基线冻结可持续的组合与阈值，然后按相同协议复验。短片和 debug smoke 只能证明接线/清理，不能自行推出持续热稳定性或整类设备预算。
5. 生产 allowlist 只接收有资格的行；当前环境不足的行保留关闭，并交接具体缺失证据。受控测试可以注入预算观测以验证准入/撤销，但注入值不写入生产 allowlist。

未知/不可采集热状态、超出帧/字节上界、预算耗尽或实际解码模式不符，都有稳定错误和有界清理。初始不准入映射 `decoder.unavailable`，运行中资源耗尽映射 `resource.exhausted`；内部 diagnostic 使用固定标识，不暴露媒体地址或任意源码文本。失败不触发降分辨率、降位深或 HDR/Dolby 降级。

## 容器、音频及 managed 边界

- PS 解复用采用现有 custom AVIO、受管 Range、取消与凭据过滤。增加 `mpeg` 所需最小 parser/module，不启用 FFmpeg 网络。时间起点、PTS wrap、缺索引与 seek 回到随机访问点分别测试，不能仅首帧即宣布支持。
- Vorbis 按规范区分 decoder overlap priming、容器 CodecDelay、DiscardPadding 和 seek preroll；以 Xiph 独立 PCM 参考验证首帧与尾端，至少覆盖 44.1/48 kHz mono/stereo、非零 delay、回零/前后 seek 和活动切轨。不能只删掉 `initial_padding == 0` 门禁。
- Opus/Vorbis 当前严格策略拒绝逐项核查。只有包、PCM、预解码窗口和网络请求确实纳入现有账本时才开放 managed/bounded；无法做到的行明确拒绝并保留缺口。
- AC-3/E-AC-3、DTS、FLAC 的已有 decoder 不重复实现；补充实际 PCM 和布局/降混验证。物理设备声道输出与软件 PCM 合格分别记录。
- MP4/MOV 错扩展名与旧系统分支先验证现有系统能力；必要时复用 owned demux/sample 路线，不能用整部预下载或取消 managed 策略绕过。

## 验证和交付

按依赖顺序完成以下阶段，每阶段先失败行为测试再实现；一个平台完成后才启动另一个平台：

1. 固定本轮调查表和失败原因；补 PS/AVC、非零 Vorbis delay、AV1/VP9 边界夹具及独立参考，保留原始失败行。
2. 修复容器/音频现有路径；PS/AVC 和 WebM/Vorbis 的本地、HTTP、改名输入通过实际生命周期、图像和 PCM 验证。
3. 增加内部解码接口、最小软件桥接及 AV1 硬件配置；五个 Apple 构建目标、许可、源码锁、制品 contract、独立复建一致性均验证。
4. 实现准入、预算、共享候选成本、取消与实际模式传播；强制硬解、故障重建、超额、未知档位、迟到回调均有测试。受控故障覆盖不能替代真实成功输出。
5. 运行合格测量、冻结有证据的档位并复验。没有足够证据时交付工程接口和关闭的生产准入行，不称“软件性能已完成”。
6. 扩展公开 `format_matrix_test.dart` 与 `decoder_budget_test.dart`，覆盖暂停、双向 seek、倍速、切音轨、后台/恢复、结束、释放及连续创建；图像来自实际播放器输出，PCM 来自真实 decoder/output 边界。
7. 回归 P01 重配、P02 字幕时标、旧音频/FEL/managed；补 API 注释、一次最终独立复核、必要修复和限定范围本地 commit。更新 P03 原计划、报告、总览与已验证支持文档。

工程测试、设备支持和外部验收继续分栏；三端未测/失败/跳过均保留。物理音画、最低 OS、Intel 实机、AV1 硬解设备和长时热证据只能由相应实际运行解除，不能用交叉编译或当前 M1 上一次成功代替。
