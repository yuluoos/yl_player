# 统一直播源解析接口并适配现有脚本

用户于 2026-09-20 确认采用统一解析接口并兼容现有 JavaScript 脚本的方案。脚本适配层获取播放地址、请求头和有效期并支持过期地址刷新；播放器内核负责解析结果对应的实际媒体协议，上层直播控制器根据真实能力选择播放路径。

相较于仅定义新脚本接口，该方案接受额外的兼容适配成本，以支持现有直播源。脚本解析成功不代表内核支持其返回的媒体协议，RTMP 必须独立接入。作出本决策时，具体兼容生态及脚本宿主能力尚待实际样本确认；本决策不承诺任意 JavaScript 脚本兼容，也未选择运行时或包归属。

2026-09-22 实施补充：冻结九份 mytvJS 原始字节，使用有界同步宿主队列与独立 QuickJS 工作线程完成解析。没有显式有效期时保持未知；刷新由业务再次调用解析，取消完成等待请求与原生运行层清理。自动切台、自动替换媒体及 RTMP 播放不由解析模块执行。逐阶段证据及三端验收状态见[实施记录](../superpowers/reports/2026-09-22-script-resolver.md)。
