# AirPlay video verification — 2026-10-19

Implementation branch: `codex/airplay-video`. No binary rebuild, private AirPlay
API, Pigeon schema change, commit, push or physical-receiver claim.

## Implemented scope

Opt-in `YlLoadOptions.airPlay`, negotiated session state and system route picker;
direct AVPlayer HLS live/VOD and MP4/MOV; bounded H.264/AAC VOD remux; LAN HTTP
serving; background/interruption gates; cancellation, replacement and disposal
cleanup. The example includes the switch, route status and host declarations.
See [usage and limits](../airplay.md).

Custom RTMP/HTTP-FLV live remux and arbitrary codec transcoding are not
implemented. Live HLS follows its original stream URL and never enters the
complete-VOD remux path.

The live test serves an AES-128 HLS playlist with five discontinuous fixture
segments and no ENDLIST, then verifies automatic inspection, original URL,
AVPlayer readiness and AirPlay opt-in. It is a live-shaped loading fixture,
not evidence of sustained sliding-window playback on a receiver.

The custom-source test uses the production HTTP byte source, real FFmpeg demux,

test substitutes the replacement video decoder so it measures resource
ownership without requiring unavailable VideoToolbox hardware. Its remux and
AVPlayer portions remain real. macOS uses the actual replacement decoder.

## Failures investigated and limits of the evidence

- A header rejection fixture initially used `Authorization` in ordinary headers,
  which the existing request validator correctly rejects before route policy.
  It now uses a valid ordinary header to test AirPlay's policy rejection.
- Flutter's route-picker factory requires a nonoptional codec result on iOS
  and an optional result on macOS; conditional signatures compile on both.
- The original one-segment live fixture did not reach AVPlayer readiness.
  The final playlist provides five segments and passes on both platforms.
- Existing macOS connection assertions counted 14 player methods, but schema 7
  has 15. Counts were reconciled to the actual generated API and AirPlay
  connection cleanup is checked separately.
- An expanded iOS run included the existing
  `YlAppleHostTests.testFailedReplacementThenReactivationPreservesAcceptedSessionControls`
  and failed with `decoder.unavailable` on this simulator. That existing test
  and its narrowly defined historical skip condition were not changed. This
  report does not claim a passing complete iOS native suite.
- The first example test invocation from the repository root failed four
  fixture-relative asset lookups. Running from the example directory passes all 96.

Review findings fixed: automatic live HLS admission, same-route background
interruption restoration, releasing retired AV remux resources on successful
non-AV replacement, macOS message handler disposal, and preserving AirPlay
state when Stop fails or its acknowledgement belongs to an older session.
