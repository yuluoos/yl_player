# RTMPS live and AirPlay verification

Date: 2026-10-19. Extends AirPlay commit `d3358712` with authenticated RTMPS
input on Apple platforms. Deployment floors stay iOS 15/macOS 12. No FFmpeg
binary or public transport options changed.

## Implementation

RTMPS addresses use port 443 by default, preserve explicit ports and tcUrl, and
enter the existing RTMP demux path for ordinary playback and AirPlay. TLS uses
Network.framework, minimum 1.2, server name, required peer authentication and
system trust. There is no plaintext fallback or production trust override.
`network.rtmp_tls_failed` is a sanitized, terminal, nonretryable error. The
existing bounded setup deadline also covers TLS, and cancellation wakes blocked
setup/read. Secure sources share RTMP live buffer defaults, seek rejection and
restoration retry gates. AirPlay normalizes automatic RTMPS to FLV/live before
source inspection and retains its existing continuous HLS worker.

Tests use a private fixture CA only inside test-supplied TLS verification,
retaining chain and hostname checks. PKCS12 identities are imported in memory
on the tested OS versions; no system keychain or trust-store modifications.

## Review and limitations

Independent read-only review found no concrete RTMPS production defect. TLS
minimum-version enforcement, DNS SNI and post-handshake TLS send/read error
classification were checked in code; dedicated runtime cases cover trust,
hostname, setup/cancel and encrypted media. Ordinary secure success proves
demux/packet delivery; actual decoded-frame evidence is on the AirPlay path.
The RTMPS reconnect test verifies the replacement map/discontinuity; the prior
[custom-live verification](2026-10-19-airplay-live.md) separately proved decoded
video beyond a discontinuity. No physical AirPlay receiver or CarPlay result is
claimed, and no complete unrelated native suite was run.

The first root test build failed due to a fixture-copy script accidentally
writing the iOS host source into the macOS route-test destination. The copy was
corrected from its canonical file before recording the expected red results.
A first decoded-frame test observed a valid frame before AVPlayerItem reported
ready; its wait now requires both milestones. The final macOS run includes
seven generic main-thread runtime warnings from fixture/host setup, with no
failed tests.

Concurrent external-playback/background work appeared in the same workspace
during execution. Those changes were preserved and excluded from RTMPS review;
final integrated builds include the workspace state. This task does not claim
verification of that separate feature.
